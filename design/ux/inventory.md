## Purpose & Player Need

玩家打开背包界面，是为了**盘点和管理自己拥有的一切物资**——查看当前持有的武器、防具、饰品、消耗品和重要物品，了解每件物品的具体作用，并据此决定**装备什么、携带什么、丢弃什么、使用什么**。

这个屏幕存在的意义在于：当物品种类增多后（武器+防具+饰品+消耗品+重要物品混杂），玩家需要快速找到"我现在能用的治疗药水还剩几个""哪件防具诅咒值更低""这个奇怪的物品到底是干什么的"——如果没有清晰的分类和详情展示，玩家会在战斗前/探索中浪费大量时间翻找，甚至因为不了解物品效果而做出错误决策（比如战斗中误用了关键剧情物品，或不知道某件装备会增加诅咒值）。

> 完成句："玩家打开背包是想要 ___"
> → **快速找到/确认某件物品并了解它的作用，然后决定如何处置它（装备 / 使用 / 丢弃 / 仅查看）**

**范围边界**：本规格仅覆盖玩家自主的背包管理（查看、分类、装备、使用、丢弃）。出售/交易等商人相关功能不在本屏幕范围内，作为独立屏幕另行设计；本屏幕的物品网格与详情侧页组件应可被未来的商店屏幕复用。

> **2026-07-17 实现基线**：每分类每页固定显示 20 种物品且页数不限；`Q/E` 切换分类，网格左右越界切页。整组丢弃，已装备物品先卸下；满 HP/MP 时对应恢复物不可使用且不消耗。本轮不实现任何诅咒效果。

## Player Context on Arrival

玩家在**野外探索阶段**（`Wilderness` / `ForestClearing` 等场景）随时可以按下背包键，打开背包界面——它是一个**暂停式覆盖层**：打开瞬间游戏世界冻结，背景以半透明显示在覆盖层之下，营造"翻开随身手记，世界静止"的氛围。

- 玩家通常是**主动**打开（检查装备、补给前确认药水数量、整理战利品），但游戏也可能在特定时刻引导（例如拾取重要物品后提示"按 Tab 查看背包"）。
- 情绪状态需要兼顾两种典型场景：
  - **从容/好奇**——主动暂停整理时，慢慢翻阅、阅读物品描述（贴近"翻阅手记"的氛围基调）；
  - **略带压力**——赶在进入危险区域前快速确认"还有几瓶药""诅咒缓解物够不够"，需要信息一目了然、操作路径短。
- 战斗内的"物品"命令是独立的轻量列表（`BattleUI.gd` 已实现），**本背包界面不在战斗中弹出**——它是探索阶段的专属屏幕，二者数据共享（同一个 `GameData.inventory`）但界面独立。

---

## Navigation Position

> 本屏幕位于：**[探索场景]（Wilderness / ForestClearing）→ 背包界面（全局热键 `Tab` 直接打开，覆盖层）**

- 背包是**顶层、随时可达**的目的地——不需要先经过暂停菜单等中间层，按一个全局热键直接打开/关闭，保持操作路径最短。
- 游戏内任意探索场景都能打开同一个背包界面实例，行为一致。

## Entry & Exit Points

| 入口来源 | 触发方式 | 玩家携带的上下文 |
|---|---|---|
| 探索场景（Wilderness/ForestClearing） | 按背包热键 `Tab` | 当前队伍状态、`GameData.inventory` 当前内容 |
| （预留）拾取重要物品提示 | 拾取后弹窗提示，玩家选择"查看背包" | 高亮刚拾取的物品 |

| 退出去向 | 触发方式 | 备注 |
|---|---|---|
| 返回原探索场景 | 按 `X`（取消/返回） | 无不可逆状态变化——背包是非破坏性的查看/整理面板，所有操作（装备切换、丢弃）即时生效但可在界面内随时再次调整，关闭即恢复游戏 |

无单向退出：玩家可以随时打开/关闭背包，不影响游戏进程或场景状态。

## Layout Specification

### Information Hierarchy

**全部信息项**：

1. 物品分类导航（武器 / 防具 / 饰品 / 消耗品 / 重要物品，每类的物品种类数）
2. 物品网格：图标 + 名称 + 持有数量
3. 选中物品的大图标 + 名称 + 所属分类
4. 选中物品的描述/世界观文本（Lore，如"聚落土法熬制的药膏"）
5. 选中物品的数值效果（恢复量/攻击力/防御力/MP消耗等，按 `effect_type`/`effect_value` 或未来的装备属性）
6. 选中物品的装备状态（武器/防具/饰品类：是否已被主角装备）
7. 当前可执行操作提示（装备/卸下/使用/丢弃/返回——随物品类型与状态变化）
8. 空分类/空背包提示

**优先级排序**：

| 优先级 | 信息项 | 理由 |
|---|---|---|
| **第一眼必须看到** | 当前选中物品的图标+名称（视觉锚点）、分类导航 | 玩家打开背包的第一反应是"我现在在看什么类、选中了什么" |
| **第二层** | 选中物品的核心数值效果（恢复量/攻击力等）+ 持有数量 | "略带压力"场景下最需要的决策依据——例如"还剩几瓶、能回多少血" |
| **第三层** | 操作提示（装备/使用/丢弃/返回） | 玩家确认完信息后下一步要做什么 |
| **第四层（详情侧页内可发现）** | 描述/Lore 文本、装备状态、（前瞻）诅咒值影响 | "翻阅手记"式的氛围信息，不影响快速决策，但补全沉浸感 |
| **状态相关** | 空分类/空背包提示 | 仅在对应状态下出现 |

**范围说明**：装备类物品（武器/防具/饰品）当前仅作用于主角一人，不需要"选择装备给哪个角色"的交互——装备状态显示为"是否已装备"的二元状态，操作为"装备/卸下"。

### Layout Zones

整体版面采用"行囊 + 夹页笔记"的隐喻：左侧/中央是深色的实体储物格（行囊内部），右侧贴着一页摊开的米黄色羊皮纸笔记（详情侧页），二者材质对比强化"打开背包翻到一页记录"的体验。整个面板外部用战斗 UI 同款 8-bit 粗黑边 9-patch 包裹，背景为半透明的冻结游戏世界。

三个区域（无常驻底部提示栏，操作菜单内嵌于详情侧页，增强沉浸感）：

1. **顶部分类书签栏**（横跨整个面板宽度，紧贴面板上沿）：5 个分类标签——武器 / 防具 / 饰品 / 消耗品 / 重要物品，每个标签显示分类名 + 该分类物品种类数角标；当前选中分类以"书签拉出/凸起"效果高亮，未选中分类略微下沉、降低饱和度。

2. **左侧/中央 — 主背包区域**（约 65~70% 宽度）：5 列 × 4 行物品图标网格，按当前选中分类过滤，每页显示 20 种物品；每格沿用 `cmd_cell_9p` 同款深色 9-patch 格子风格，格内右下角标注持有数量（消耗品/战斗道具类）。方向键移动焦点=实时预览，按 `Z` 选中后格子高亮加粗；底部留白显示页码。

3. **右侧 — 详情侧页**（约 30~35% 宽度）：视觉上是一页摊开的米黄色羊皮纸笔记，与左侧深色行囊格形成材质对比。自上而下：选中物品大图标 + 名称 + 分类小标签 → 数值效果（恢复量/攻击力/防御力等）→ 分隔线 → 描述/Lore 文本（衬线/手写体模拟笔记感）→（装备类追加）装备状态。按 `Z` 选中网格中的物品后，底部展开 `ActionMenu`（操作选项列表，如"使用/丢弃"或"装备/丢弃"），按 `X` 收起返回预览态。

### Component Inventory

**① 顶部分类书签栏**

| 组件 | 类型 | 内容 | 可交互 | 模式引用 |
|---|---|---|---|---|
| `CategoryTab` ×5 | 标签按钮 | 分类名（武器/防具/饰品/消耗品/重要物品）+ 物品种类数角标 | 是（左右切换选中分类） | **新模式**：「书签标签」——选中态"拉出/凸起"，未选中态下沉降饱和度 |

**② 主背包区域（行囊网格）**

| 组件 | 类型 | 内容 | 可交互 | 模式引用 |
|---|---|---|---|---|
| `ItemGrid` | 网格容器 | 5 列 × 4 行，20 格/页 | 容器本身不交互 | 新布局，沿用 `cmd_cell_9p` 格子皮肤 |
| `ItemSlot` | 网格项 | 物品图标（来自 `assets/ui/items/`）+ 右下角持有数量 | 是（方向键移动焦点=预览详情，Z=选中进入操作菜单） | 复用战斗 UI **命令格高亮**模式（`BattleUI.gd` 中 `_render_central_options` 的选中高亮逻辑） |
| `EmptySlotGhost` | 网格项（占位） | 半透明分类图标轮廓 | 否 | 新模式 |
| `EmptyCategoryHint` | 提示文本 | "此分类暂无物品" | 否 | 沿用战斗 UI 文本+描边字体样式 |

> **不透明度规则**：`ItemData.usable == false` 的物品，其 `ItemSlot` 图标整体降至 50% 不透明度，与可使用物品形成视觉区分（典型场景：重要物品分类中的纯收藏品）。该规则与是否可丢弃无关——不可使用的物品仍可能在 `ActionMenu` 中提供"丢弃"选项。
>
> **图标缺失兜底**：若物品没有对应的图标资产（`ItemData.icon` 字段未配置或资源加载失败），`ItemSlot` 与 `ItemIconLarge` 显示统一占位图标（如问号格），不留空白——确保在图标资产补齐前界面仍可正常使用与验收。

**③ 详情侧页（羊皮纸笔记）**

| 组件 | 类型 | 内容 | 可交互 | 模式引用 |
|---|---|---|---|---|
| `ItemIconLarge` | 图标 | 选中物品大图标（2x 放大） | 否 | 复用 `assets/ui/items/` 资产 |
| `ItemNameLabel` | 文本 | 物品名称 | 否 | 沿用 `battle_theme.tres` 字体样式（米白字+深色描边） |
| `CategoryChip` | 标签徽章 | 当前分类小标签 | 否 | 复用战斗 UI `chip_status.png` 模式 |
| `StatBlock` | 数值列表 | 效果数值（如 "HP +30"、"攻击力 +5"） | 否 | **新模式**：「物品数值条目」 |
| `Divider` | 分隔线 | 笔记纸上的手绘分隔线 | 否 | 新视觉元素 |
| `DescriptionText` | 文本 | 物品描述/Lore（衬线/手写体模拟） | 否（过长时可滚动） | 新字体样式 |
| `EquipStatusBadge` | 状态徽章 | "已装备"/"未装备"（仅武器/防具/饰品显示） | 否 | **新模式** |
| `ActionMenu` | 内嵌操作菜单 | 按 Z 选中物品后，在描述文本下方展开的操作选项列表（如"▶ 使用 / 丢弃"或"▶ 装备 / 丢弃"），按 `usable`/`discardable`/装备状态动态生成；若均不可执行则显示灰色"（无可执行操作）" | 是（方向键在选项间移动，Z 确认执行，X 收起返回网格预览态） | **新模式**：「侧页内嵌操作菜单」——复用战斗 UI 中央选项列表的选中高亮视觉（`_render_central_options`），嵌入羊皮纸详情页内 |
| `EmptyDetailHint` | 提示文本 | 背包完全为空时的占位文案 | 否 | 沿用文本样式 |

**④ 弹窗组件（覆盖整个背包界面之上）**

| 组件 | 类型 | 内容 | 可交互 | 模式引用 |
|---|---|---|---|---|
| `DiscardConfirmDialog` | 模态确认框 | "确定丢弃 [物品名] x[数量]？" + `[Z] 确认` `[X] 取消` | 是（在 `ActionMenu` 中选择"丢弃"并按 Z 后触发，二次确认防误删重要物品/装备） | **新模式**：「丢弃二次确认」——小尺寸 9-patch 弹窗，居中浮于背包界面之上，背包输入暂时冻结直到弹窗关闭 |

## States & Variants

| State / Variant | Trigger | What Changes |
|---|---|---|
| **默认/预览态** | 打开背包（`Tab`），或在操作选择态按 `X` 收起 | 主背包网格中焦点格高亮（细描边）；详情侧页实时显示焦点物品信息；无 `ActionMenu` |
| **操作选择态** | 预览态下对焦点物品按 `Z` | 网格选中格高亮加粗；详情侧页底部展开 `ActionMenu`，显示按 `usable`/`discardable`/装备状态动态生成的 1~2 项操作 |
| **无可执行操作** | 操作选择态下，该物品 `usable=false` 且 `discardable=false` | `ActionMenu` 仅显示一行灰色"（无可执行操作）"；方向键/Z 无效，仅 `X` 可收起 |
| **装备类·未装备** | 焦点/选中物品为武器/防具/饰品，且当前未装备 | `EquipStatusBadge` 显示"● 未装备"；`ActionMenu` 选项为"装备 / 丢弃" |
| **装备类·已装备** | 同上但已装备 | `EquipStatusBadge` 显示"◆ 已装备"；`ActionMenu` 选项为"卸下 / 丢弃" |
| **丢弃二次确认** | `ActionMenu` 中选中"丢弃"并按 `Z` | `DiscardConfirmDialog` 居中弹出，背包输入冻结，显示"确定丢弃 [物品名] x[数量]？" |
| **不可使用物品（视觉态）** | 物品 `usable=false`（如"旧怀表"） | 该 `ItemSlot` 图标整体降至 50% 不透明度，与可用物品区分；可正常聚焦/选中 |
| **空分类** | 当前选中分类下物品种类数为 0 | 网格区域显示 `EmptyCategoryHint`"此分类暂无物品"；详情侧页显示 `EmptyDetailHint`；该分类无法进入操作选择态 |
| **空背包** | 全部 5 个分类物品种类数均为 0 | 5 个分类标签角标均为 `(0)`；详情侧页文案为"行囊空空如也 / 什么都没有。" |
| **未知物品（错误兜底）** | `GameData.inventory` 中的条目引用了 `ItemData` 数据库中不存在的物品（存档版本升级/数据迁移后的脏数据） | `ItemSlot` 显示统一占位图标；详情侧页名称显示"未知物品"、描述显示"无法辨认的东西。"；`ActionMenu` 仅提供"丢弃"选项，便于玩家清理脏数据 |

## Interaction Map

**输入方式**：纯键盘——方向键（导航）+ `Z`（确认/选中）+ `X`（取消/返回/收起），与战斗 UI（`BattleUI.gd` 的 `CONFIRM_KEY`/`CANCEL_KEY`）一致；无手柄/触屏支持。

| 组件 / 状态 | 操作 | 输入 | 即时反馈 | 结果 |
|---|---|---|---|---|
| 全局 | 打开背包 | 探索场景中按 `Tab` | 覆盖层淡入，背景世界半透明冻结 | 进入 Inventory 界面，游戏暂停 |
| 全局 | 关闭背包 | 默认/预览态下按 `Tab` 或 `X` | 覆盖层淡出 | 退出 Inventory 界面，游戏恢复 |
| `CategoryTab` | 切换分类 | `Q/E` | 旧标签下沉，新标签"拉出"高亮；`ItemGrid` 刷新为新分类内容，恢复该分类上次页码和焦点 | `ItemGrid` 过滤条件变化（仅 UI 状态） |
| `ItemSlot` | 移动焦点（预览） | 方向键 `↑↓←→` | 焦点格描边高亮；详情侧页内容实时切换为新焦点物品 | 仅 UI 状态变化 |
| `ItemGrid` | 切换页面 | 焦点位于首/末列时继续按 `←`/`→` | 切换上一/下一页并把焦点放到相邻边缘格；首末页不循环、无页面时焦点留在原位 | 仅 UI 状态变化；每分类记忆页码和焦点 |
| `ItemSlot` | 选中物品 | `Z` | 选中格高亮加粗；详情侧页底部展开 `ActionMenu` | 进入"操作选择态" |
| `ActionMenu` | 切换选项 | `↑↓` | 选项高亮切换（复用 `_render_central_options` 高亮视觉） | 仅 UI 状态变化 |
| `ActionMenu`（使用） | 使用消耗品 | `Z`（焦点在"使用"） | 应用效果反馈（待音效/动画补充）；持有数量 -1，归零则从网格移除；对应 HP/MP 已满时置灰且不消耗 | 写 `GameData.inventory`；应用 `effect_type`/`effect_value` 到主角 |
| `ActionMenu`（装备/卸下） | 切换装备状态 | `Z`（焦点在"装备"或"卸下"） | `EquipStatusBadge` 切换；`ActionMenu` 选项随之刷新 | 写主角装备状态（存储结构见 Data Requirements） |
| `ActionMenu`（丢弃） | 发起丢弃 | `Z`（焦点在"丢弃"） | 弹出 `DiscardConfirmDialog` | 进入"丢弃二次确认"，暂不写数据 |
| `ActionMenu` | 收起菜单 | `X` | `ActionMenu` 收起，选中格恢复细描边焦点态 | 返回"默认/预览态" |
| `DiscardConfirmDialog` | 确认丢弃 | `Z` | 弹窗关闭；整组物品从网格移除；焦点回退到相邻物品或 `EmptyCategoryHint`，空页回退到上一有效页 | 调用 `GameData.discard_item`——**若该物品已装备，先自动卸下再移除**（防止装备槽残留悬空 `item_id`） |
| `DiscardConfirmDialog` | 取消丢弃 | `X` | 弹窗关闭，输入解冻 | 返回"操作选择态"，不写数据 |

## Transitions & Animations

| 场景/状态变化 | 动画 | 时长/缓动 | 备注 |
|---|---|---|---|
| 进入背包界面 | 覆盖层淡入 + 背景世界同步变暗至半透明 | ~150ms，linear | 像素风格下避免缩放/位移造成锯齿抖动 |
| 退出背包界面 | 覆盖层淡出，背景恢复正常亮度 | ~150ms | 与进入对称 |
| 切换分类 | 选中书签"拉出/凸起"，`ItemGrid` 内容即时刷新 | 0ms（即时切换） | 8-bit 风格倾向即时反馈而非过渡动画 |
| 选中物品 → 展开 `ActionMenu` | 从描述文本下方向下展开（高度 0→目标值） | ~100ms，ease-out | 强调"翻开笔记追加一行"的质感 |
| 收起 `ActionMenu` → 预览态 | 反向收起 | ~100ms，ease-in | |
| 弹出 `DiscardConfirmDialog` | 中心缩放弹出（scale 0.8→1.0 + 淡入） | ~120ms | |
| 关闭 `DiscardConfirmDialog` | 反向（缩小 + 淡出） | ~100ms | |
| 确认丢弃后物品移除 | 该 `ItemSlot` 图标淡出 + 轻微缩小，随后变为 `EmptySlotGhost` | ~150ms | 给玩家"物品消失"的明确反馈 |

**减弱动画/晕动症**：所有动画时长 ≤150ms 且无持续闪烁或大幅位移，当前设计不需要专门的 reduced-motion 开关；若未来加入更长的位移/缩放动画，应在 Accessibility 章节补充开关选项。

## Data Requirements

本屏幕需要的数据与现有 `ItemData`（`game/scripts/resources/ItemData.gd`）/`GameData.inventory` 之间存在多处缺口：

```gdscript
enum ItemType { CONSUMABLE, BATTLE_ITEM, PALLIATIVE }
enum EffectType { HEAL_HP, HEAL_MP, DAMAGE, REDUCE_CURSE }
@export var id, display_name, description, item_type, effect_type, effect_value
```

| Data | Source System | Read/Write | Notes |
|---|---|---|---|
| 持有物品列表 + 数量 | `GameData.inventory`（`Array[Dictionary]` `{item: ItemData, count: int}`） | Read | 现有结构可直接使用 |
| 物品名称/描述 | `ItemData.display_name` / `description` | Read | 现有字段可用 |
| 消耗品数值效果 | `ItemData.effect_type` / `effect_value` | Read | 现有字段可用，仅覆盖消耗品类 |
| **物品分类**（武器/防具/饰品/消耗品/重要物品） | ⚠️ **缺失** — 现有 `item_type` 枚举（CONSUMABLE/BATTLE_ITEM/PALLIATIVE）与 5 类分类不对应 | Read | 需新增分类字段或扩展/重构枚举 |
| **物品图标** | ⚠️ **缺失** — `ItemData` 无 `icon` 字段 | Read | `game/assets/ui/items/*.png` 已有 7 个图标资产（item_shardstone / item_throwing_knives / item_bandage_kit / item_ash_salve / item_glimmer_water / item_black_sack / item_red_pouch），尚未与 `ItemData` 关联 |
| **装备数值**（攻击力/防御力等） | ⚠️ **缺失** — 现有数值字段面向消耗品效果，无装备属性字段 | Read | 武器/防具/饰品需要新数值字段 |
| **装备状态**（已装备/未装备） | ⚠️ **缺失** — `GameData` 无装备槽数据 | Read/Write | 需新增装备槽结构（武器/防具/饰品各一槽，存 `item_id` 或 `null`） |
| **`usable` / `discardable` 标志** | ⚠️ **缺失** — `ItemData` 无此字段 | Read | 驱动 `ActionMenu` 内容与 50% 不透明度规则；当前无法表达"旧怀表不可使用"这类情况 |
| 分类种类数角标（`CategoryTab`） | 派生自 `GameData.inventory` + 分类字段 | Read | 依赖上述分类字段缺口解决 |

**架构缺口汇总——已决策（2026-06-11）**：采用"单一 ItemData 平铺扩展 + GameData 三槽装备字典 + 单一写入者"方案：
1. 物品分类：`ItemData` 新增 `category` 枚举（武器/防具/饰品/消耗品/重要物品 5 类），与现有 `item_type`（战斗语义）正交保留，不重构后者
2. 物品图标：`ItemData` 新增 `icon: Texture2D` 字段，直接引用 `assets/ui/items/` 资产
3. 装备数值：`ItemData` 新增 `attack_bonus` / `defense_bonus` 平铺字段
4. 装备槽：`GameData` 新增三槽装备字典（武器/防具/饰品 → `item_id`，空字符串 = 未装备）
5. 标志位：`ItemData` 新增 `usable` / `discardable` 布尔字段

> 否决的备选：`EquipmentData` 子类（当前规模收益小）、重构 `ItemType` 枚举（与战斗语义正交且破坏 `BattleUI.gd` 依赖）、Dictionary 属性包（失去强类型）。
> 物品 `.tres` 存放于 `assets/data/items/`（手工维护数据资源例外区，见 `game/CLAUDE.md` §1）。

## Accessibility

| 检查项 | 评估 |
|---|---|
| **键盘导航路径** | 全部可交互元素可达：`CategoryTab` ↔ `ItemGrid`（边缘切换）；`ItemGrid` 内 `↑↓←→` 移动；选中后 `ActionMenu` 内 `↑↓` 切换选项、`Z` 确认、`X` 收起；`DiscardConfirmDialog` 仅 `Z`/`X` 两个固定操作，无需方向键 |
| **手柄导航顺序** | N/A——本游戏确认为纯键盘，无手柄支持（Phase 2h 已确认）；若未来加入手柄，应复用上述键盘焦点顺序映射到方向键/确认键/取消键 |
| **文本对比度与最小字号** | 复用 `battle_theme.tres`：米白字 `Color(0.847,0.812,0.753,1)` + 深色描边 `Color(0.086,0.078,0.102,0.9)`，`outline_size=2`，`default_font_size=18`，在深色行囊格与米黄色羊皮纸两种背景上对比度均充足；若详情侧页引入手写体装饰字体，正文（`DescriptionText`/`StatBlock`）应保留默认无衬线字体，手写体仅用于装饰性标题 |
| **不依赖颜色传达信息** | ① 不可使用物品的 50% 不透明度规则不依赖颜色；② 装备状态用"●未装备"/"◆已装备"符号区分而非仅颜色；③ 分类标签的选中/未选中用"拉出/凸起 vs 下沉"的位置+形状变化区分 |
| **屏幕阅读器考量** | 本游戏为纯像素 2D RPG，Godot 默认无 TTS/屏幕阅读器基础设施；所有图标元素（`ItemIconLarge`/`ItemSlot`）均配有 `ItemNameLabel`/`CategoryChip` 等文本标签，为未来可能的集成保留基础 |
| **动画 reduced-motion** | 见 Transitions & Animations——所有动画 ≤150ms 且无持续闪烁，当前不需要专门开关 |

⚠️ **缺口**：项目尚未定义 Accessibility Tier（`design/accessibility-requirements.md` 不存在）。建议以 WCAG-AA 为基线，并通过 `/gate-check` 确认是否会阻塞 Pre-Production 门槛。该缺口同步写入 Open Questions。

## Localization Considerations

项目目前为纯中文，尚无本地化系统；以下为未来翻译时的版面约束记录：

| 元素 | 中文示例 | 翻译扩展风险 | 处理建议 |
|---|---|---|---|
| `CategoryTab` 标签 | 武器/防具/饰品/消耗品/重要物品（2~5字） | **高**——英文如 "Accessories"(11)/"Consumables"(11)/"Key Items"(8) 远超中文宽度 | 标签宽度需按最长翻译预留，或采用图标+短文本组合 |
| `ActionMenu` 选项 | 使用/丢弃/装备/卸下（2字） | **高**——英文 "Discard"(7)/"Unequip"(7) | 菜单框宽度按最长操作词预留，或自适应内容 |
| `EquipStatusBadge` | 未装备/已装备（3字+符号） | **高**——英文 "Not Equipped"(12) | 徽章宽度自适应，或采用纯符号+悬浮文本方案 |
| `ItemNameLabel` | 灰烬药膏/微光水（3~5字） | 中——英文物品名长度不一 | 超长名称截断+省略号，或允许最多 2 行 |
| `DescriptionText` | 数十字 Lore 文本 | 低——已设计为"过长时可滚动" | 滚动机制天然吸收翻译扩展 |
| `DiscardConfirmDialog` 文案 | "确定丢弃 [物品名] x[数量]？" | 中——动态插入物品名，弹窗宽度固定 | 弹窗宽度按最长物品名+操作文案预留，超长名称截断 |
| `StatBlock` 数值 | "HP +30"、"攻击力 +5" | 低——纯数字+符号，无货币/日期格式 | 数字部分不受语言影响；标签文本遵循上述通用规则 |

**最高优先级**：`CategoryTab` 与 `ActionMenu` 两处空间最受限，是后续翻译时最容易"撑爆"布局的元素。

## Acceptance Criteria

- [ ] 在探索场景中按 `Tab` 后，背包界面在 200ms 内完成淡入并进入可交互状态（覆盖层动画完成、首个物品获得焦点）

- [ ] 方向键移动焦点时，详情侧页（图标/名称/分类/数值效果/描述）实时更新为当前焦点物品的信息
- [ ] 同一分类有 21 种物品时可通过网格横向越界进入第 2 页；删除第 21 种后自动回到第 1 页，首末页不循环
- [ ] `Q/E` 切换分类并恢复各分类上次页码和焦点；所有文字与图标在 1920×1080 和 1280×720 下不越出指定区域
- [ ] 恢复物对应 HP/MP 已满时“使用”置灰，直接调用数据接口也失败且不扣数量
- [ ] 当某分类下物品种类数为 0 时，主背包网格显示"此分类暂无物品"，详情侧页显示"行囊空空如也"占位文案，且无法进入操作选择态
- [ ] 按 `Z` 选中物品后，`ActionMenu` 显示的选项与该物品的 `usable`/`discardable`/装备状态一致（例如：可用消耗品显示"使用/丢弃"，未装备武器显示"装备/丢弃"，`usable=false` 且 `discardable=false` 的物品显示"（无可执行操作）"）
- [ ] 在操作选择态选择"丢弃"并按 `Z` 后弹出 `DiscardConfirmDialog`；按 `X` 取消则返回操作选择态且不修改 `GameData.inventory`，按 `Z` 确认则正确从背包中移除/扣减该物品
- [ ] 全部可交互元素（分类标签、物品格、操作菜单选项、丢弃确认弹窗）均可仅用方向键 + `Z`/`X` 完成导航和操作，无需鼠标
- [ ] 在预览态/操作选择态/空背包态之间切换时，按 `X` 始终能逐级返回（操作选择态→预览态→关闭背包），不会跳过层级或卡死
- [ ] 在项目标准内部渲染分辨率下，所有 9-patch 边框、物品图标与文字保持像素级对齐，无非整数缩放导致的模糊或边缘错位（`default_texture_filter=0` Nearest 下验证）
