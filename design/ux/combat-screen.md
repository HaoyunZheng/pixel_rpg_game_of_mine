## Purpose & Player Need

回合制战斗是「星辰之烬纪元」核心循环的关键一环——玩家进入战斗画面，是为了在"我方 1~4 人（含主角）vs 敌方 1~2 人"的对局中，**看清当前局势、为当前行动者选择并执行一个指令（行动/技能/物品/逃跑），并在攻击时通过力度转盘获得一次主动操作反馈**。

这个屏幕存在的意义在于：本作的战斗没有运气成分（无暴击/闪避随机波动，伤害公式确定），玩家的每一次胜负几乎完全取决于**信息是否被清楚传达**——谁的回合、敌我双方 HP/MP 还剩多少、谁正被谁锁定、诅咒值是否已经在拖累某个角色的技能消耗。如果这个屏幕信息混乱或氛围松散，玩家会：

- 因为看不清"谁要打谁"而错失最优指令；
- 感受不到"诅咒在侵蚀战斗"这一世界观核心机制（诅咒/羁绊状态在当前实现中完全不可见）；
- 因为大片空黑画面而失去"身处阴郁废土"的代入感，战斗退化成对着黑屏点菜单。

> 完成句："玩家进入战斗画面是想要 ___"
> → **快速看懂当前战局（轮到谁、敌我状态、谁在被谁盯上），从容地选择行动，并在攻击时刻获得一次有分量的操作反馈——同时被这个被诅咒侵蚀的世界持续包裹。**

**范围边界**：本规格覆盖战斗的"指令选择"静态 HUD（七分层：顺序条 / 敌方区 / 中央框 / **演出框** / 命令栏 / 我方状态列 / 准星层，我方状态列支持 1~4 人）、行动/技能/物品二级列表（行动子项含**攻击/防御/闪避**三种姿态）、攻击力度转盘、**敌方回合的中央框+演出框联动扩张态**（演出框播敌人攻击动画、中央框作为我方受击演出区域）、以及战斗结算（胜负）提示。

**不在范围内**：
- Boss 战特殊形态——暂不设计，未来方向记录于 Open Questions；
- 受击弹幕的具体判定数值（无敌帧 / 弹反窗 / 倍率档等）——归玩法数值设计（见《战斗系统文档》§3 / 附录 B.4）。

## Player Context on Arrival

玩家在**野外探索区**（梦召道沿途）操控主角移动时，**主动或失误触碰明雷敌人**进入战斗——这是核心循环里的"遭遇阶段"。明雷机制意味着战斗几乎总是"看见了才打"：玩家要么主动选择接战（清巡逻、拿掉落），要么是规避失败被碰到。

- **之前在做什么**：在野外移动、调查痕迹、拾取物资——节奏舒缓、注意力分散在探索上。战斗入场是一次**节奏的硬切换**：从自由漫游切到回合制对峙，转场必须把这个"心理换挡"做出来（见 Transitions & Animations）。
- **情绪状态假设**：紧张但可控。本作是 Soul-like 调性 + 资源稀缺，玩家进战斗时带着"我的药还够不够、这场值不值得打"的盘算；战斗不是爽快宣泄，而是步步为营的资源博弈。UI 应支持**从容的信息阅读**（无倒计时压力，指令选择不限时），但氛围要持续传达压迫感。
- **到达方式**：被动进入（触碰即战斗，无确认弹窗）。玩家无法在"进入战斗"这一刻反悔——规避决策发生在地图上，不在本屏幕。

## Navigation Position

> 本屏幕位于：**[野外探索区]（Wilderness 等场景）→ 战斗画面（独立场景 Battle.tscn，SceneManager 切换）**

- 战斗画面是**封闭式独立场景**，不是覆盖层——进入后探索场景卸载，战斗结束后由结算决定去向。
- 玩家**不能**从战斗画面打开背包（`Tab` 失效）、不能呼出其它系统界面——战斗内的物品使用走命令栏"物品"的轻量列表（与 `design/ux/inventory.md` 已确认的边界一致）。
- 战斗中无暂停菜单（MVP 范围）。

## Entry & Exit Points

| 入口来源 | 触发方式 | 玩家携带的上下文 |
|---|---|---|
| 野外探索区 | 触碰明雷敌人（碰撞即触发，无确认） | 队伍当前 HP/MP/诅咒值、`GameData.inventory`、敌方配置（哪只敌人、1~2 体）；BattleManager 复制一份战斗数据副本 |
| （预留）偷袭先制 | 背后接触（扩展阶段，《通用文档》§7.6） | 额外携带 `ambush={side,type}`，偷袭方开局多一轮 |

| 退出去向 | 触发方式 | 备注 |
|---|---|---|
| 返回野外探索区 | **胜利**（敌方全灭）→ 结算掉落 → 转场 | 战斗副本数据写回 GameData（HP/MP 消耗、物品增减）；**单向**：战斗过程不可重来 |
| 返回**上一个存档点** | **失败**（我方全灭） | 丧失 50% 金钱与主角的当前升级经验进度，死亡位置留下"遗落光点"可拾回（见 States & Variants）；HP/MP 重置、**诅咒值保留**；战斗副本数据丢弃；单向 |
| 返回野外探索区 | **逃跑成功**（命令栏"逃跑"，概率判定） | 不获得掉落；HP/MP 消耗保留写回 |
| （留在本屏幕） | 逃跑失败 | 消耗当前行动者回合，战斗继续 |

所有出口都是**单向且系统驱动**的——玩家无法用 `X` 或任何取消键"退出战斗画面"，只能通过胜利/失败/逃跑三个机制出口离开。这是与背包等覆盖层界面的本质区别。

## Layout Specification

### Information Hierarchy

**全部信息项**：

1. **当前轮到谁行动**（行动者名称/标识）
2. **行动顺序队列**（本轮接下来谁行动，pip 条）
3. **敌方状态**：立绘本身（**无名称、无 HP 条**——沉浸感优先；目标名称仅在锁敌时显示于中央框，命中反馈靠受击闪烁传达，不提供任何血量读数或低血量暗示）
4. **我方每人状态**：头像、姓名、HP 条+数值、MP 条+数值、**诅咒侵蚀头像框**（诅咒达到一定阶段时头像框周围出现紫色缠绕物，通过替换头像框 sprite 实现，缠绕量随阶段加重；**平稳时为普通头像框**——克制原则，仅当诅咒实际影响战斗时才出现）
5. **中央框内容**：单条战况文字 / 二级选项（技能列表含 MP 消耗与置灰态、物品列表含图标+数量+置灰态）
6. **命令栏四格**：行动/技能/物品/逃跑 + 各自可用性（如无可战斗用物品时"物品"置灰）
7. **锁定关系**：我锁敌（金色准星浮于敌头像）、敌锁我（红色标记浮于我方头像，扩展阶段配合姿态系统）
8. **演出框**：当前己方角色的战斗动画（新增分层；敌方回合时联动扩张，见 Layout Zones）
9. **攻击力度转盘**（覆盖态：档区+指针+倍率/档名）
10. **战斗结算提示**（胜利/失败 + 掉落信息）
11. **背景氛围**（阴郁森林——非"信息"但是必须存在的体验层，缺失=黑屏点菜单）

**优先级排序**：

| 优先级 | 信息项 | 理由 |
|---|---|---|
| **第一眼必须看到** | ① 当前轮到谁 + ⑤ 中央框文字/选项 | 回合制战斗的"现在该做什么"——中央框是铁律主角（《战斗系统文档》§B.3） |
| **第二层** | ④ 我方 HP/MP/诅咒侵蚀头像框 | 决策依据：还能挨几下、出手还稳不稳 |
| **第三层** | ⑥ 命令栏 + ② 顺序条 + ⑦ 锁定关系 | 行动入口与战术预判（下一个是敌人的回合吗？它盯着谁？） |
| **第四层（氛围/演出）** | ⑧ 演出框动画 + ⑪ 背景 | 不承载决策信息，但承载"被世界包裹"的体验 |
| **状态相关（仅特定时刻）** | ⑨ 转盘（攻击时覆盖）/ ⑩ 结算（战斗结束时） | 临时覆盖态，出现时即为当时的第一优先级 |

**已确认的两个层级判断**：
- **诅咒值进入第二层**（决策信息而非装饰）：以头像框紫色缠绕物呈现（躁动/侵蚀/濒临三档缠绕量递增），平稳时为普通头像框；**不使用 chip**。诅咒的战斗影响为：转盘失误档占比随等级扩大（20%/40%/70%/85%）、不完美格挡 MP 消耗稍增、闪避位移稍减（详见《通用文档》§4.3 修订版）。
- **敌方不显示任何常驻 HP/名称信息**（修订版，原为"只有条、无数字"）：沉浸感优先；亦不做低血量状态暗示，玩家对敌方血量的感知完全来自战斗过程本身。

### Layout Zones

**编排方案**：方案 C「左柱 + 通高演出框」（已确认）。
**基准画布 480×270**（×4 = 1920×1080），所有坐标与尺寸按此基准描述。整体遵守"中央框是主角"铁律（《战斗系统文档》§B.3）。共 1 个背景层 + 7 个 UI 分层 + 3 个临时覆盖态。

#### 各分层详细规格

**⓪ 背景层**（全屏 480×270，z 最底）
- 程序化阴郁森林背景（`bg_battle_forest.png`）**铺满全屏**，敌人立绘"站"在背景地平线上，不再浮在黑色虚空里。
- 背景整体压暗：上深下浅微渐变 + 四角轻微暗角（vignette），保证其上所有 UI 文字可读。
- **当前实现中背景完全不可见（截图为纯黑），修复此问题是本次美术改进的第一优先级。**

**① 顶部行动顺序条（弧线滚动式）**（y 2~30，水平居中，总宽约 200px）
- 底层是一条**上凸的横向圆弧线**（1px 骨白低 alpha，自绘 `draw_arc` 弧段）。
- 各单位的行动顺序以**头像球**（圆形裁剪的头像 sprite + 圆形描边框，**不放文字**）沿弧线**等距**呈现：中央 = 当前行动者，最大（18×18，描金 + 下指示符）；向两侧逐级缩小（±1 → 14×14，±2 → 11×11，±3 → 8×8），最边缘的球仍能辨认是谁。
- 左右两侧各最多 3 个头像球（含中央共最多 7 个可见位）。
- **行动变更动画**（回合开始 / 上一个角色行动结束）：所有头像球沿弧线**从右往左**滑动一格；最左端（与中央距离为 3）的球**缩小并淡出**销毁；右侧新进入队列的球（若有）在最右端**对称地放大淡入**。
- 头像未接入前用阵营色圆形占位球（友蓝/敌红）。
- 资产：原 `pip_turn` / `pip_turn_active` 退役；头像球圆框可程序化绘制（`draw_circle` / `draw_arc`）。

**② 敌方区**（y 28~110，敌人 1~5 体整体居中排列）
- 每体敌人 = **立绘直接站在背景上**——无边框、**无名称、无 HP 条**，最大化沉浸感。
- 排列：1~5 体整体居中，间距随数量自适应（5 敌时每体占宽约 88px，立绘较宽时允许轻微重叠站位、近大远小）。
- 信息的替代呈现：
  - **目标名称**：锁敌选择时由中央框文字显示（如"▶ 猎手"）——名字只在需要的瞬间出现在主角框里，不常驻头顶；
  - **命中反馈**：受击时立绘闪烁/伤害演出，仅确认命中，不传达血量；
  - 锁敌时当前目标立绘正常亮度 + 金色准星，非选中目标轻微压暗（沿用现有逻辑）。

**③ 中央框**（x 98~358（宽 260），y 152~234（高 82），9-patch `panel_central_9p`）
- 贴底偏上：左边让出我方状态列、右边让出演出框。
- **文字编排**：框内文字区至少容纳 **3 行**；常态单条战况文字**靠左排列**，位于框内**上 1/3 区域**（左内边距 ~10px）。
- **二级选项（防重叠 + 两列）**：打开行动子项/技能/物品列表时，选项以**两列网格**在框内**下 2/3 区域**展开，上 1/3 的**原战况文字保持原样不变**（不替换为"使用哪个物品？"之类的操作提示，也**不添加操作提示标题行**），两区物理分离永不重叠。列表超出两列容量时分页/滚动，具体见 Component Inventory 与 States & Variants。
- 高度比当前实现压缩约 1/3：当前中央框过高、内部大片留白稀释了"主角感"；82px 在本基准下仍是最大单体 UI 面板，主角地位不变。

**④ 演出框**（x 364~456（宽 92），y 152~262（高 110，**通高**——顶边与中央框平齐、底边与命令栏底边平齐），9-patch 同款边框）
- 常态：显示**当前行动的己方角色**的战斗立绘/动画（idle / 施法 / 攻击起手），纵向 portrait 比例。
- 无人行动的间隙（转场、敌方回合扩张前）：显示暗化空舞台或当前行动敌人的剪影。
- 敌方回合行为见"扩张态"。

**⑤ 命令栏**（x 98~358，y 240~262（高 22），与中央框同宽、贴其下沿）
- 四格固定：行动 / 技能 / 物品 / 逃跑，格子沿用 `cmd_cell_9p` 切片风格。
- 不可用命令置灰但保留位置（如无可战斗用物品时"物品"灰显）。

**⑥ 我方状态列**（x 6~92（宽 86），底边贴 y 262 向上生长）
- 纵列，每人一张卡，支持 1~4 人，**所有人数统一同一种卡式**（不做样式切换）：卡高 26px、卡间距 2px——头像 16×16 + 姓名 + HP 条带数字 + MP 条带数字；姓名右侧预留小图标位（8×8，最多 3 个，放 debuff / 姿态标记）。4 人总高 110px，**顶边与中央框顶边（y 152）平齐，任何情况下不超过中央框上沿**。
- 当前行动者的卡片左缘亮一条余烬橙竖线（2px）。
- **诅咒侵蚀头像框**：角色诅咒达到躁动/侵蚀/濒临时，其头像框替换为对应等级的"紫色缠绕"变体 sprite（缠绕量递增：角部藤蔓 → 半圈 → 整圈+微光）；平稳时为普通 `avatar_frame_9p`。**不使用 chip**。新资产：头像框诅咒变体 ×3。

**⑦ 准星/锁定层**（叠加层，z 最顶）
- 金色准星（`reticle_target_gold`）：我锁敌时浮于被选敌人**立绘上方**。
- 红色锁定标记：敌锁我时**环形描边围绕被锁己方角色的头像一圈**（扩展阶段配合姿态系统启用，本轮只定位置）。注：现有 `marker_locked_red.png`（18×12 椭圆+文字底）需重制为环形切片，记入资产需求。
- **出现动画**：金色准星与红色锁定环在出现/切换目标时播放一个简短小动画——**旋转 + 淡入**（约 0.2s 量级，具体参数见 Transitions & Animations）。
- **确认动画（"锁死目标"脉冲演出）**：玩家确认攻击/技能使用时，金色准星 sprite **小幅内缩并迅速回弹**至原尺寸；回弹完成后在同一位置生成一个**准星副本** sprite，持续放大、不透明度渐减至 0 后销毁该实例。红色准星（敌锁我）在**敌方行动回合开始时**先在被锁己方头像上播放同一套确认动画，之后才进入敌方攻击与己方受击画面（扩张态）。

#### 三个临时覆盖态

**A. 攻击力度转盘**
- 转盘**居中放置于中央框区域内**；转盘底板**不透明**（灰烬底实心，完全遮住框内原内容）。命令栏在转盘期间弱化且不可交互。

**B. 敌方回合扩张态**（新设计）
- 触发：轮到敌人行动时。
- 动效：中央框**向上扩张至 y≈28**（覆盖敌方区，顺序条保留可见），**同时向左扩张至 x≈6**（完全覆盖我方状态列）；命令栏暂时消失。扩张后中央框约 352×234；演出框位置不变、向上通高至 92×234。
- 内容：演出框播放该敌人的**攻击动画**；中央框作为**我方受击演出区域**——只播我方角色的受击动画/特效，**不显示受击文字**。未来的弹幕判定演出直接复用这块扩张区域，无需再改版式。
- 结束：敌人行动结算完毕，两框回落原位，命令栏恢复。

**C. 战斗结算**
- 胜利/失败文字与掉落信息进中央框显示（不另开弹层），详细行为见 States & Variants。

#### 演出与镜头预留（phantom-camera 适配）

- 镜头方案已确定使用第三方插件 **[phantom-camera](https://github.com/ramokz/phantom-camera)**（开发者批准的红线例外，需同步更新 `game/CLAUDE.md`，见 Open Questions）。
- 所有动态演出与战斗交互（攻击、受击、弹反、转盘定格、扩张/回落等）的触发点，必须经由**统一的演出编排接口**（工作名 `BattleStage`）执行；该接口内部通过 **PhantomCamera2D 虚拟机位的 priority 切换与 tween** 实现镜头运动（shake / zoom / pan）。
- 战斗场景预置若干 PCam2D 虚拟机位（候选：全景机位、敌方区特写、演出框/受击特写——具体机位清单与镜头语言留待后续演出设计）。
- UI 层动效（框扩张/回落）与镜头运动由同一编排接口同步触发，避免两套时序各自为政。
- 本规格只约定"接口必须存在且所有演出走它"；此条同时记为架构关注点（见 Data Requirements 与 Open Questions）。

| **二级选项态** | 命令栏选中"行动/技能/物品"按 `Z` | 中央框下 2/3 两列选项展开（**行动子项 = 攻击 / 防御 / 闪避**；技能列表；物品列表），上 1/3 原文字不变；焦点落首个可用项；`X` 收起返回命令栏 |
| **姿态保持态** | 行动子项选"防御"或"闪避"按 `Z` | **无目标选择**，立即生效并结束该角色回合；该角色状态卡姓名旁出现姿态小图标（盾形=防御 / 残影形=闪避，骨白 8×8）；姿态保持至**该角色的下一个行动回合**开始时自动清除；受击结算按姿态执行（防御减伤——不完美格挡的 MP 消耗随诅咒等级稍增；闪避位移——距离随诅咒等级稍减） |
| **选项置灰变体** | MP 不足的技能 / 缓解物 / 数量为 0 后的物品 | 对应条目置灰但保留位置；焦点跳过置灰项 |
| **选项翻页变体** | 可选项 > 6（2 列×3 行） | 显示翻页指示 ▼；焦点移动到页尾继续下移时自动翻页 |
| **目标选择态** | "攻击"或需要目标的技能/物品确认后（**防御/闪避不进入此态**） | 敌方目标（仅攻击与攻击型技能/物品）：当前目标立绘正常亮度+金色准星（旋转+淡入），其余敌人压暗；中央框显示"▶ [目标名]"；我方目标（治疗/物品）：焦点在状态卡间移动、当前卡高亮；`X` 返回上一步 |
| **准星确认演出** | 目标上按 `Z` 确认攻击/技能 | 金色准星小幅内缩→迅速回弹原尺寸→同位置生成放大+渐透明至 0 的准星副本后销毁（"锁死目标"脉冲）；随后进入转盘/执行 |
| **力度转盘态** | 攻击指令确定目标后 | 转盘居中于中央框、底板不透明；命令栏弱化不可交互；**失误档占比按当前角色诅咒等级缩放：平稳 20% / 躁动 40% / 侵蚀 70% / 濒临 85%**，其余档（完美/良好/普通）在剩余占比内按原比例缩放；`Z` 定格 → 显示档名/倍率 → 短暂停留后关闭 |
| **行动执行演出** | 指令全部确认完毕 | 演出框播放攻击/施法动画；命中时敌方立绘受击闪烁、伤害数字弹出；我方 HP/MP 条与数字即时刷新 |
| **敌方回合扩张态** | 轮到敌人攻击己方 | **先**在被锁己方头像上播放红色准星确认动画（内缩回弹+副本放大淡出）→ 中央框+演出框扩张（向上至 y≈28、中央框向左至 x≈6 覆盖状态列）、命令栏消失 → 演出框播敌人攻击动画、中央框播我方受击演出（**无文字**）→ 结算后回落复位 |
| **敌方上 debuff 演出** | 敌人对己方角色施放 debuff | 走扩张态同款流程（红色准星确认动画 → 扩张）；演出框播敌人施法动画，中央框播目标角色被**诅咒紫雾缠绕**的演出（无文字）；回落后目标状态卡闪紫一次，姓名旁出现 debuff 小图标（8×8 诅咒紫底；MVP 最小集：眩晕/中毒） |
| **敌方互 buff 演出** | 敌人对敌方单位（含自身）施放 buff | **不扩张**：施法敌人立绘短暂亮起+施法粒子；目标敌人立绘被**血红色上升粒子**环绕（~0.8s）；中央框单条文字播报（如"✦ 猎手的气息变得凶戾。"）；敌方**不显示** buff 图标——存在感靠演出与后续伤害变化传达（沉浸原则） |
| **逃跑判定** | 命令栏"逃跑"按 `Z`（无需目标） | 成功：中央框"✦ 成功逃离了战斗。"→ 转场返回野外；失败：中央框"✦ 没能逃掉——[姓名]的回合结束了。"，回合被消耗 |
| **诅咒侵蚀头像框变体** | 我方角色诅咒值 ≥ 躁动 | 该角色状态卡头像框替换为对应等级紫色缠绕变体（躁动=角部藤蔓 / 侵蚀=半圈 / 濒临=整圈+微光）；平稳=普通框 |
| **倒地态** | 我方角色 HP 降至 0 | 状态卡**保留**：整卡去饱和+约 50% 压暗、头像灰化、HP 数字 0 显示血红；该角色退出行动顺序（弧线条上其头像球缩小淡出移除）、**无法行动**；敌我双方的目标选择均**无法选中**该角色；我方未全灭则战斗继续 |
| **队伍人数变体（1~4）** | 入场队伍配置 | 状态卡 1~4 张（统一 26px 卡式贴底向上）；顺序条头像球数随之变化 |
| **敌人数量变体（1~5）** | 入场敌方配置 | 敌方区立绘居中自适应分布；5 体时允许轻微重叠站位 |
| **胜利结算** | 敌方全灭（ActionResolve 判定） | 中央框显示"✦ 战斗胜利！"+ 掉落物文字清单（如"获得了 灰烬药膏 x1"，不开战利品弹层）；任意确认键后转场返回野外；**被击败的明雷敌人实例从野外地图移除**（当前实现存在不移除的 bug，修复任务见 Open Questions/实现侧） |
| **失败结算** | 我方全灭 | 中央框显示失败文字；**丧失 50% 金钱与主角的当前升级经验进度**；短暂停留后转场返回**上一个存档点**（HP/MP 重置、诅咒值保留）；死亡位置生成"遗落光点"实例（见下方扩展设计） |

> 已确认裁剪：诅咒"濒临"阶段的"失神跳过回合"表现**暂不做**（新版诅咒机制中跳过回合本身已被移除，见《通用文档》§4.3 修订版）。

### 失败结算扩展：死亡遗落（Death Cache）

> 此实例存在于**野外探索场景**，不在战斗画面内，但作为失败结算流程的组成部分在此规格化。特效设计参考 godot-prompter:particles-vfx skill。

**机制流**：
1. 战斗失败 → `GameData` 记录 `{lost_gold, lost_exp_progress, scene, position}`（position = 触发战斗的死亡位置）→ 玩家返回上一个存档点。
2. 对应野外场景 `_ready` 时检测到遗落记录 → 在记录位置实例化 `DeathCache`。
3. 主角靠近（**圆形距离判定**：`global_position.distance_to(player.global_position) < 16px`，物理帧轮询或 Area2D 圆形 CollisionShape）→ 触发回收 → 返还全部遗落金钱与经验进度 → 实例销毁、记录清空。

**视觉规格（常驻态）**——白色发光、悬空、边缘模糊的光点：
- `GPUParticles2D` 连续发射：`amount≈12`、`lifetime≈1.6s`、`one_shot=false`、`preprocess≈2.0`（防止入场时粒子突然出现）、`emission_shape=SPHERE` 半径 3px、初速 2~4px/s 朝上（`direction=(0,-1,0)`、`spread=180°`）、`gravity=(0,0,0)`（悬空不坠落）、`scale_curve` 1.0→0.0、`color_ramp` 纯白 α0.9 → α0；务必设置 `visibility_rect`。
- 贴图：8×8 软边圆（高斯衰减）——该光点是"非物质灵光"，**允许例外地打破硬边像素规则**以表达"边缘模糊"；若坚持像素一致性可用 dithering 软圆替代。
- 悬浮感：粒子节点本体用 Tween 做 ±2px、周期 ~2s 的正弦上下浮动。
- 微光：叠一盏低能量 `PointLight2D`（白色、energy≈0.4、半径≈24px）。

**回收动画（玩家靠近触发）**：
- 常驻粒子 `emitting=false`（存量自然消亡）。
- "飞向主角"：生成 8~12 个独立小 `Sprite2D`（4×4 白点）+ 各自 Tween（随机延迟 0~0.15s、时长 0.3~0.5s、`TRANS_EXPO`/`EASE_IN`）直线飞向玩家**实时位置**后逐个销毁——独立 Sprite+Tween 方案比纯粒子方案能精确命中移动中的玩家，数量小、成本可忽略。
- 全部到达后：主角 modulate 闪白一次（0.1s），返还金钱与经验进度，`DeathCache.queue_free()`。

**依赖缺口**：金钱、经验/等级、存档点三个系统目前均未实现（Demo 阶段无此三者），死亡遗落依赖其先行落地——记入 Open Questions。

## Interaction Map

**输入方式**：纯键盘——方向键/WASD（导航）+ `Z`（确认）+ `X`（取消/返回），与全项目键位约定一致（《通用文档》§1.2"键盘即手柄"）；无鼠标、无手柄、无触屏。战斗中 `Tab`（背包热键）失效。

| 状态 / 组件 | 操作 | 输入 | 即时反馈 | 结果 |
|---|---|---|---|---|
| 命令栏 | 切换命令 | `←`/`→`（A/D） | 金色指针+描边移到新格；置灰格被焦点跳过 | 仅 UI 状态 |
| 命令栏 | 确认命令 | `Z` | "行动/技能/物品"：中央框下 2/3 两列选项展开；"逃跑"：直接进入逃跑判定 | 进入二级选项态 / 逃跑结算 |
| 二级选项（两列网格） | 移动焦点 | `↑↓←→`（WASD） | 金色描边+指针在网格内四向移动；置灰项跳过；焦点在页尾继续下移时自动翻页（▼ 指示刷新） | 仅 UI 状态 |
| 二级选项·攻击 | 确认 | `Z` | 进入目标选择：首个合法敌人立绘亮起+金色准星旋转淡入，其余压暗 | 进入目标选择态 |
| 二级选项·防御/闪避 | 确认 | `Z` | **无目标选择**：状态卡姓名旁姿态小图标出现（盾/残影）；中央框文字播报（如"✦ [姓名]摆出了防御的架势。"） | 写入该角色 `pending_stance`；回合立即结束，顺序条滚动 |
| 二级选项·技能/物品 | 确认 | `Z` | 攻击型→敌方目标选择；治疗/增益型→我方目标选择（状态卡间焦点） | 进入目标选择态 |
| 二级选项 | 收起返回 | `X` | 选项网格收起，焦点回到命令栏原命令格 | 返回指令选择态 |
| 目标选择（敌方） | 切换目标 | `←`/`→` | 金色准星旋转+淡入移到新目标立绘上方；新目标恢复亮度、旧目标压暗；中央框"▶ [目标名]"刷新 | 仅 UI 状态 |
| 目标选择（我方） | 切换目标 | `↑`/`↓` | 焦点在状态卡间移动、当前卡高亮（倒地角色跳过） | 仅 UI 状态 |
| 目标选择 | 确认目标 | `Z` | **准星确认脉冲动画**（内缩回弹+副本放大淡出）；攻击→转盘升起；技能/物品→直接进入执行演出 | 锁定目标；进入转盘态 / 执行 |
| 目标选择 | 取消 | `X` | 准星淡出，敌方立绘恢复，回到二级选项网格（焦点保留原项） | 返回二级选项态 |
| 力度转盘 | 定格 | `Z` | 指针定格，显示档名/倍率，短暂停留后转盘关闭 | 倍率写入攻击者；进入执行演出（**无 `X` 取消**——起转即不可反悔） |
| 执行/结算演出 | （无操作） | 输入封锁 | `Z`/`X` 均不响应（《战斗系统文档》§B.3：结算阶段不可取消） | 演出完毕自动推进 |
| 敌方回合扩张态 | （无操作，MVP） | 输入封锁 | 同上；**预留**：未来弹幕演出在此态接管 WASD（移动判定点）+ `Shift`（冲刺）+ `Z`（弹反） | 演出完毕回落，推进下一行动者 |
| 胜利结算 | 确认离开 | `Z` | 转场开始 | 返回野外（敌人实例已移除） |
| 失败结算 | （无操作） | 输入封锁 | 短暂停留后自动转场 | 返回上一个存档点，死亡处生成遗落光点 |

**焦点规则补充**：
- 任何时刻屏幕上**有且仅有一个**金色焦点（命令格 / 选项格 / 目标准星 / 我方目标卡），避免双焦点歧义。
- 二级选项打开时默认焦点 = 首个**可用**项（跳过置灰）；从目标选择 `X` 退回时恢复退出前的焦点项。
- 倒地角色（HP=0）在我方目标选择中被跳过（不可选中）。

## Events Fired

本项目无分析系统，事件 = 游戏内信号（供 BattleManager / GameData / 演出层解耦用）。

| 玩家操作 | 触发事件 | Payload / 数据 |
|---|---|---|
| 切换命令 / 焦点移动 / 翻页 / 收起菜单 | 无事件（纯 UI 状态） | — |
| 选定姿态（防御/闪避） | `stance_selected` | `actor_id`, `stance`——写战斗副本内的 `pending_stance`，不持久化 |
| 转盘定格 | `wheel_resolved`（**已有信号**，AttackPowerWheel） | `multiplier`, `tier_name` |
| 攻击/技能执行完毕 | `action_executed` | `actor_id`, `action_type`, `target_id`, 结果数值（伤害/治疗量）——演出层与镜头（BattleStage）订阅此事件 |
| 战斗内使用物品 | `item_used`（**GameData 已有**） | `item_id`——⚠️ 写背包（战斗副本，胜利才写回） |
| 逃跑 | `escape_attempted` | `success: bool` |
| 我方角色倒地 | `unit_downed` | `unit_id`——顺序条移除头像球、状态卡切倒地态均订阅此事件 |
| 战斗结束 | `battle_ended`（**已有**，Battle.gd） | `victory`——⚠️ 胜利：写回 HP/MP/物品 + `mark_enemy_defeated`；失败：触发死亡惩罚链 |
| （失败自动）死亡惩罚 | `death_penalty_applied` | `lost_gold`, `lost_exp_progress`, `scene`, `position`——⚠️ 写 GameData 持久化遗落记录 |
| （野外）遗落回收 | `death_cache_recovered` | `gold`, `exp_progress`——⚠️ 写回 GameData，清空遗落记录 |

⚠️ **架构关注点**：
1. 所有持久化写入仍走"BattleManager 战斗副本 + 胜利单点写回"的既有契约（《通用文档》§B.2），事件只做通知不直接改数据。
2. `death_penalty_applied` / `death_cache_recovered` 依赖金钱、经验、存档点三个未实现系统，事件名先约定、字段后补。
3. 演出与镜头一律经 BattleStage 订阅事件触发，不在战斗逻辑里直接调镜头。
