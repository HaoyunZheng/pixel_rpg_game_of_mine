# 星辰之烬纪元 — 对话系统文档

> 文档版本：v2.0 拆分版 · 对话篇
> 关联：世界观基调见《通用文档》§1.1；羁绊/营火对话、任务、NPC 阵营翻转等系统在《通用文档》。

> **文档定位（务必先读）**：本篇是对话/文本系统的**整体规划文档**，正文只规定**风格、体验目标与方案架构**，**不收录任何具体对话台词/剧情文本**（台词由文案在大纲 v3 的指导下另行填充）。覆盖范围：文本与对话风格、痕迹叙事（碎片化叙事的承载方式）、对话框与文本呈现、对话系统的顶层方案。实现层细节下沉到文末 **附录 B**。

> **2026-07-17 当前实现基线**：Dialogic 管理剧情阶段、分支选择、NPC 叙事关系和任务叙事进度；`GameData` 管理背包、装备、队伍、战斗、敌人事实、羁绊与诅咒。当前只做一个流浪者样板，不做正式剧情、本地化、自动演出框架或磁盘存档。

---

## 1. 范围与定位

**本篇负责**：
- 对话与描述文本的统一**风格**基调。
- **痕迹叙事**：可调查物、遗物说明、营火对话、NPC 对话所承载的碎片化叙事方式。
- **对话框与文本呈现**的设计（逐字、翻页、头像、布局）。
- 对话系统的**顶层方案架构**（内容管理 / 状态协调 / 表现方案 / 触发入口 / 跨系统挂钩）。

**本篇不负责**：
- 具体对话台词、分支剧情内容（属文案，依据剧情大纲 v3 填充）。
- NPC 阵营翻转/好感、任务系统的机制本体（在《通用文档》；本篇只提供它们调用对话的"挂钩点"）。
- 战斗内文本（伤害日志、受击演出提示）属《战斗系统文档》。

---

## 2. 文本与对话风格

文本是本作传达"阴郁、压抑、被命运裹挟"的主要载体之一，须与《通用文档》§1.1 的基调一致：

- **克制、留白**：少用感叹与煽情，靠信息的缺口与冷静的笔触制造压迫。恐怖来自"结构本身"，而非夸张措辞。
- **碎片化、立场化**：不同来源（壁画 / 遗物 / 不同 NPC）给出的信息**各自局限、彼此可能矛盾**，让玩家自行拼凑，而非由旁白直接交代真相。
- **描述式叙事**：遗物/可调查物采用"魂系物品描述"式的短文——以物言史，暗示而不明说。
- **节奏**：文本**逐字显示**，营造低语般的推进感；描述与对话共用同一套呈现节奏。
- **语气随状态变化（可选扩展）**：高诅咒/重度状态下的同伴台词可变得失稳——此为表现层挂钩，不在本篇定义具体文本。

> 本篇只定义风格"准绳"；具体遣词由文案按此准绳与大纲 v3 产出。

---

## 3. 痕迹叙事（碎片化叙事的承载）

这个世界的历史被主动埋葬，真相只能从痕迹里渗出。Demo 通过以下方式承载碎片化叙事（均经统一文本管线呈现，见 §4、§5）：

- **可调查物**：壁画、遗物、尸骸——走近可调查，给出一段描述文字。不同痕迹给出的信息**各自局限、立场不同**，玩家自行拼凑全貌。
- **遗物说明**：拾取的遗物带有说明文字，暗示其来历与前朝历史（魂系物品描述式叙事）。遗物作为物品的归类与库存见《通用文档》库存系统。
- **营火对话**：随羁绊解锁的同伴背景揭示（羁绊机制见《通用文档》§4.1）。
- **NPC 对话**：安全区 NPC 提供局部视角的历史碎片。

> 参考方向：魂系物品描述、Outer Wilds 的线索拼凑。Demo 规模：一个小废墟 + 5~6 个可调查物（彼此信息互补或张力对照）+ 1~2 个 NPC。

---

## 4. 对话框与文本呈现

设计层目标：呈现服从基调——压暗背景、不抢戏、逐字推进。具体参数（尺寸、透明度、节点）下沉至附录 B。

- **布局**：对话框占屏幕底部约 1/4，半透明黑底压暗背景；左侧头像区，右侧文本区，说话者名字小标签置于头像旁。
- **逐字显示**：文本逐字浮现，制造低语层次；可一键跳过逐字、翻页推进。
- **头像**：随说话者/情绪轻微变化（占位期用偏色近似）。
- **可调查物/遗物描述**：复用同一对话框/文本框承载（无头像或用物件图），与对话保持一致观感。
- **与战斗的关系**：战斗内对话框在受击演出中会被放大为弹幕场边界——该用途的实现归《战斗系统文档》，本篇只保证对话框组件可被复用与缩放。

---

## 5. 系统方案架构

对话系统采用"内容统一管理、状态外置协调、表现独立承载、触发入口收敛"的方案。正文只规定设计职责与协作边界；具体实现细节见附录 B。

**内容管理层**：对话正文、可选分支、角色表情、调查描述和剧情自动演出顺序由统一内容管线管理。文案只维护文本意图、分支条件、角色表现与演出节奏，不直接处理玩法结算或长期状态。

**状态协调层**：Dialogic 变量直接持有剧情阶段、分支选择、NPC 叙事关系和任务叙事进度；timeline 用原生 Condition/Set 事件读取和推进这些叙事变量。背包、装备、队伍、战斗、敌人事实、羁绊与诅咒仍由 `GameData` 持有，timeline 只能通过只读查询将其作为世界条件。

**表现方案层**：正常对话、可调查物描述、遗物说明、营火对话和自动演出中的文本提示共享统一的低饱和暗色基调、逐字节奏、头像 / 表情表现和键盘推进规则。表现层不决定剧情结果；战斗中央框 / 弹幕场复用仍归《战斗系统文档》，本篇只保证视觉与输入原则不冲突。

**触发入口层**：触发来源包括 NPC 交互、营火对话（羁绊阶解锁）、可调查物 / 遗物描述、周目锚点 NPC、NPC 阵营翻转的转场台词，以及非对话的剧情自动演出。所有触发都进入统一入口，避免同类叙事内容出现多套启动方式。

**跨系统挂钩（只定义方案，不定义具体台词）**：
- **剧情标志**：Dialogic timeline 可直接读取和写入其拥有的剧情阶段、分支与 NPC 叙事变量。
- **羁绊 / 任务**：羁绊是 `GameData` 玩法数据，timeline 只读；任务的叙事进度归 Dialogic，未来若出现玩法奖励，由独立玩法入口结算。
- **NPC 阵营翻转**：对话分支可触发 NPC 立场变化（机制见《通用文档》附录 B 的 NPC 阵营翻转设计）。
- **周目识别**：锚点 NPC 可根据周目状态切换既视感台词（见《通用文档》§7.3）。
- **本地化准备**：文本内容必须与显示语言解耦，便于后续多语言、校对和文案替换。
- **剧情自动演出**：非对话剧情段落可与对话共享叙事编排，但实际场景动作由项目表现系统承接；具体技术分工见附录 B。

> 本篇是"框架与挂钩"，把"对话怎么运转、怎么和其他系统对接"定清楚；"对话说什么"留给文案，按 §2 风格与大纲 v3 填充。

| 术语 | 含义 |
|---|---|
| **痕迹叙事** | 通过可调查物、遗物说明、对话碎片让玩家自行拼凑被埋葬历史的叙事方式 |
| **描述式叙事** | 以物件短描述暗示历史的写法（魂系物品描述风格） |

| **剧情自动演出** | 无需玩家逐句推进的剧情段落，由 Dialogic 编排、项目脚本执行场景动作 |

## 附录 B：技术实现参考（对话）

> 收录对话系统的引擎/代码级实现细节。目标引擎 Godot 4.x。全局数据/场景结构（`GameData`、剧情标志位、`SceneManager` 等）定义见《通用文档》附录 B。

### B.0 Dialogic 插件接入

本项目采用 **Dialogic 2** 作为对话编辑与运行时播放承载层。Dialogic 是对话内容、剧情阶段、分支选择、NPC 叙事状态、任务叙事进度、角色表现和 style 的权威；项目层保留 `DialogueManager` 薄包装作为统一入口和播放生命周期边界。

- 插件来源：`https://github.com/dialogic-godot/dialogic.git`
- 当前接入版本：`2.0-alpha-19`（release zip commit `0dd7da25b26708f17da727d32771e2c23ffdad3f`，Godot 4.4+）
- 工程目录：`res://addons/dialogic`
- Godot 启用项：`project.godot` 的 `[editor_plugins] enabled` 包含 `res://addons/dialogic/plugin.cfg`
- AutoLoad：`Dialogic` 指向 `res://addons/dialogic/Core/DialogicGameHandler.gd` 的 UID，由 Dialogic 编辑器插件启用流程写入。
- 输入动作：`dialogic_default_action` 用于推进 Dialogic 文本；正式交互需按《通用文档》§B.1 清理为键盘闭环，以 `Z` 推进 / 确认、`X` 取消 / 返回为准。
- 许可证：MIT，随 vendored 插件保留在 `res://addons/dialogic/LICENSE`

**使用边界**：
- Dialogic 负责编辑器内的 character / timeline / style 配置、逐字播放、选项展示、角色表情切换和运行时 timeline 播放。
- 项目层的触发入口必须收敛到 `DialogueManager` 或等价包装层，外部系统不要直接散落调用 Dialogic API。
- `GameData` 继续作为背包、装备、队伍、战斗、敌人事实、羁绊和诅咒的权威；timeline 对这些数据只读。
- 本轮 timeline 可直接保存样板中文文本；正式剧情和本地化在内容规模需要时再接入。

**后续集成建议**：
- 首个样板使用 `story.flags.met_forest_wanderer` 与 `story.branches.forest_wanderer` 验证首次选择和重复分支。
- 世界条件通过 timeline 直接调用 `GameData.is_enemy_defeated("Enemy1")` 等只读查询，不复制为 Dialogic 变量。
- 对话结束只恢复控制并发出生命周期信号；不再使用 `set_flags`、`bond_add` 等结果回流钩子。

### B.1 Dialogic 资源与目录规范

- Dialogic timelines：按场景 / NPC / 主线段落组织，资源名与项目层 `dialogue_id` 一一对应或通过注册表映射。
- Dialogic characters：维护角色显示名、portrait、基础 mood / expression key；同一角色不得在多个 character 资源中重复定义。
- Dialogic styles / layouts：正常对话、可调查物描述、剧情自动演出可使用不同 style，但都遵守底部文本框、低饱和暗色、键盘闭环的统一原则。
- localization：正式剧情扩张时再接入 Godot `TranslationServer` / CSV 或 PO；本轮不创建本地化框架。
- 对话资产不放入 `assets/`；使用现有 `res://dialogue/timelines/`，Character 与 Style 保存到 `res://dialogue/` 下对应目录。

### B.2 对话 UI 与输入参数

- 对话框占屏幕底部约 1/4，半透明黑底 `Color(0,0,0,0.8)` 压暗背景；可叠一层极淡灰烬 / 裂纹底纹。
- 左侧头像区由 Dialogic character portrait 承载；右侧文本区由 Dialogic typewriter 承载，默认节奏约每字符 0.03s，可按 style 配置。
- `Z`：通用确认；逐字中补全文本，文本完整后推进到下一条，选项中确认当前项。
- `X`：通用取消 / 返回；按 B.6 的跳过规则退出、跳过或忽略。
- WASD / 方向键：在选项列表中移动选择。
- 不把非键盘输入写成主操作；调试期如保留其它输入映射，也不得成为正式交互规范。
- 正常对话 UI 由 Dialogic 自定义 style/layout 承载；战斗中央框放大为弹幕场的用途归《战斗系统文档》附录，本篇不规定战斗 UI 节点。

### B.3 角色表情与 portrait 规范

- 基础 expression key：`neutral`、`sad`、`angry`、`fear`、`hurt`、`soft`、`unstable`。
- `neutral` 是每个角色的默认表情，必须存在或可由默认 portrait 代替。
- `unstable` 用于高诅咒、精神失衡、阵营翻转前兆等状态表现；是否触发由 `GameData` 状态或 timeline 分支决定。
- 资产不足时允许用默认头像、占位色、轻微 `modulate` 或简化 portrait 代替，但 timeline 中仍使用稳定的 expression key，避免后续替换资产时改文案。
- 角色名字、头像、表情变化由 Dialogic character 与 timeline 驱动；项目脚本只提供触发上下文和状态条件。

### B.4 控制层接口与状态同步

- `DialogueManager`（AutoLoad 或等价单例）接口：`start(dialogue_id: String, context := {})`。
- `dialogue_id` 映射到 Dialogic timeline；映射可由注册表、常量表或资源表提供，但外部系统只持有 `dialogue_id`，不直接持有 Dialogic 资源路径。
- 开始前：校验注册的 timeline，保证播放互斥；不复制 `GameData` 状态。
- 播放中：项目层可监听 `Dialogic.timeline_ended`、`Dialogic.signal_event(argument)`、`Dialogic.text_signal(argument)` 等运行时信号；具体监听方式以实现时 Dialogic API 为准。
- 结束后：项目层发出结束信号并恢复玩家/场景输入，不回写剧情、羁绊、诅咒或其它玩法数据。
- 叙事变量只存在 Dialogic；玩法与世界事实只存在 `GameData`，禁止复制成两套权威。

### B.5 触发与集成挂钩

- NPC 交互体、营火、可调查物、遗物描述、周目锚点、NPC 阵营翻转转场均调用 `DialogueManager.start(dialogue_id, context)`。
- `context` 可携带触发节点、NPC id、调查物 id、当前场景、允许跳过标记、结束回调等运行时信息；它不保存台词正文。
- 叙事分支读写 Dialogic 变量；玩法世界条件直接调用 `GameData` 只读查询，timeline 不调用其写接口。
- 可调查物 / 遗物描述可使用无头像或物件 portrait 的 Dialogic style，仍走同一套 key、本地化、输入和结束回流规则。

### B.6 跳过 / 取消策略

- 主线首次剧情自动演出默认不可跳过；`X` 只可在安全节点返回或被忽略，避免误跳关键叙事。
- 重复播放的剧情、营火对话、可调查物文本可允许 `X` 跳过或退出。
- 是否可跳过由 `dialogue_id` 的注册信息、timeline 元数据或启动 `context` 标记决定。
- 逐字显示期间按 `Z` 只补全文本，不视为跳过整段对话。
- 跳过时必须走统一结束流程，恢复玩家控制并清理临时 UI / 演出状态。

### B.7 剧情自动演出

> **延期**：本轮不实现自动演出、信号动作协议或 `CutsceneDirector`；以下仅保留长期方向，不是当前交付要求。

- 非对话剧情自动演出由 Dialogic timeline 编排顺序，项目层执行实际场景动作。
- timeline 中可插入 Dialogic 信号事件表达"需要项目执行某个动作"；项目层监听后交给未来 `CutsceneDirector` 或等价场景脚本处理。
- 可表达的动作类型包括角色移动、播放动画、镜头移动 / 缩放、淡入淡出、等待、切换场景、写入剧情 flag、临时锁定 / 恢复玩家控制等；本篇不锁死具体事件名。
- 自动演出期间默认禁用玩家移动和普通交互；选项选择、确认推进或允许跳过的节点仍遵守 `Z/X` 规则。
- 自动演出结束必须回到项目层，由项目层恢复输入并按需触发 `SceneManager` 或后续系统。

### B.8 当前运行期状态边界

- 本轮不实现磁盘存档；Dialogic 变量只保证当前运行期间跨场景保留。
- 未来统一存档读取 `Dialogic.get_full_state()`，与 `GameData` 玩法数据一同落盘；在存档任务立项前不增加桥接或序列化抽象。
