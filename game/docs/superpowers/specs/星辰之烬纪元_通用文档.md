## 1. 游戏概述

| 项 | 内容 |
|---|---|
| **游戏类型** | 回合制 RPG（后日谈 + 黑暗幻想 + Soul-like 调性） |
| **核心体验** | 在被遗忘的废土上探索、遭遇明雷敌人、进入回合制战斗、在"羁绊"与"诅咒"的双重压力下管理有限资源 |
| **视角** | 俯视角 2D 像素风 |
| **目标平台** | PC |
| **Demo 目标** | 验证「探索 → 遭遇 → 战斗 → 返回/整备 → 再出发」核心循环是否有趣、清晰并可重复游玩 |
| **素材策略** | 占位素材先行，玩法验证后再接入真实素材 |

### 1.1 世界观基调

世界经历过两场大规模毁灭——大裂变（数百年前）与终焉之战（约七十年前）。第二次毁灭中，被绝望民众尊为救世主的"伪神"陨落，世界自此进入"静默"：魔法表面枯竭，文明退回小型聚落自给自足的形态。

但静默不是和平。一百二十年前的伤口被时间埋葬，野外散布着仍在自动运转的远古机制：苍白帝国时代的魔像、空间裂隙、变异生物、燃烬者残躯。近年又出现新现象——**梦召**：某些曾接触过古代遗迹（因而身上留下"共鸣印记"）的人，开始做同一个梦，被催促前往世界深处一个无人归来的地方；若拒绝前往，他们会在一段时间内痛苦地死去。

玩家扮演的不是"在末日中醒来的幸存者"，而是一个**普通聚落的青年，在迁徙途中无意被古代残留法则烙下共鸣印记，从此开始接收梦召**。他出发不是因为天选，而是因为留下不是选项。沿途遇到的同伴各自带着派系余烬与未愈合的伤口。

整体氛围阴郁、压抑、危险，但能够在人与人之间找到人性与希望的光芒——**不是传统 JRPG 的冒险感，而是被命运裹挟、步步为营的求生感**。世界的恐怖不来自具象反派，而来自**结构本身**：没有人在操控这场悲剧，而它仍在重复。在探索这个世界的同时，玩家通过痕迹逐步揭露被埋葬的历史。

### 1.2 核心设计理念

- **资源稀缺**：恢复手段有限，每个决策都有代价。当前 Demo 先验证 HP/MP 与消耗品管理；缓解物与诅咒压力留待长期系统立项。
- **明雷威胁**：敌人可见且危险，玩家可选择战斗或规避。规避在剧情上对应"绕过拦截派的巡逻"等。
- **羁绊即风险（长期方向）**：队伍成员各有派系背景与战术定位。与同伴加深羁绊会带来战斗收益与叙事回报，也会加快诅咒增长；完整设计保留在 §4，但不进入当前 Demo。
- **死亡是循环的一部分**：失败不是结束。这一原则在剧情层有更深含义——主角的轮回是地点的属性而非天赋。MVP 阶段不实现轮回，但在少量物件上预留周目识别入口（详见 §7.3）。
- **自由探索无代价，推进主线有代价（长期方向）**：诅咒时钟未来只绑定主线推进，不绑定自由漫游；当前 Demo 不运行这条时钟（详见 §2.2、§4.4）。
- **键盘即手柄**：游戏默认以全屏模式打开，核心交互不依赖鼠标；`Z` 作为通用确认键，`X` 作为通用取消/退出键。UI、战斗与对话的所有可操作流程都必须能只用键盘完成。

## 2. 核心玩法循环（MVP）

```
        进入野外/梦召道
安全区 ───────────────→ 野外探索区
(恢复/整备)               (探索/挖痕迹/遇敌)
  ↑                         │
  │   返回 / 失败重来        │ 触碰明雷敌人
  └─────────────────────────┤
                            ↓
                       回合制战斗
                            │
            胜利 ───────────┼─────────── 失败
             ↓                          ↓
        获得物品                    返回安全区
        返回野外                    HP/MP 重置
```

### 2.1 循环说明

1. **探索阶段**：玩家在梦召道沿途的野外区自由移动，可见敌人巡逻，可拾取散落物资（废墟残物、遗物碎片），可调查痕迹（壁画、遗物、尸骸）拼凑历史。
2. **遭遇阶段**：主动触碰敌人进入战斗（明雷机制，可规避）。
3. **战斗阶段**：回合制指令战斗，主角 + 1 队友 vs 1~2 敌人；战斗流程见《战斗系统文档》。
4. **结算阶段**：胜利获得物品并返回野外；失败返回安全区并重置 HP/MP。
5. **恢复阶段**：在安全区（聚落 / 路边废墟篝火 / 灼的礼拜堂等）休息点恢复 HP/MP、进行整备并再次出发。

### 2.2 两条时钟的分离（长期设计铁律，不进入当前 Demo）

游戏中存在两类"前进"，必须严格分离：

- **空间前进（自由、无代价）**：在大世界中漫游、探索、绕路、挖痕迹、完成请托。**不推进诅咒。** 玩家可以无限期自由活动。
- **命运前进（玩家主动选择、有代价）**：推进主线节点。**只有这时诅咒值上涨。** 也正是在这一刻，玩家可选择使用缓解物为同伴下压诅咒（见 §4.5）。

这条铁律同时服务三个目标：保留开放世界的自由度；不背叛"被命运裹挟"的故事（迟早得走的存在性压迫感）；为 §4 的诅咒系统提供干净的增长触发点。

> 梦召在大世界中通过非强制手段表现：(1) 主角始终隐约感知源头方向（可忽略的氛围指引）；(2) 诅咒钟绑定主线而非移动；(3) 世界对"被召者"身份做出区别反应（不同派系区别对待你）。世界对你做出反应，而非限制你的路径。

## 3. 角色与队伍

> 角色的完整背景、创伤、派系余烬、命运轨迹见剧情大纲 v3 第 10 节。本节只描述 Demo 阶段的玩法定位。

### 3.1 Demo 阵容

| 角色 | 是否被召者 | 战斗定位 | 备注 |
|---|---|---|---|
| **玩家**（主角） | 是 | 中庸近战，玩家固定视角 | 始终在场 |
| **1 名同伴** | 是 | 支援/治疗 或 高输出近战 | Demo 的战术互补角色 |

**同伴选择建议**：Demo 采用 1 名治疗支援型同伴，让战斗资源循环完整；关系成长留到长期羁绊系统。

> **队伍规模（以《战斗画面 UX Spec》为准）**：战斗系统与 UI 按**我方 1~4 人**（含主角）设计——状态列、行动顺序、目标选择均不绑死人数。Demo 阵容默认 2 人（主角 + 1 同伴），但 1~4 人为系统支持上限，便于后续扩展同伴位与临时同行角色。

### 3.2 角色数据（机制层字段）

Demo 每个角色需要记录：唯一标识、显示名、HP/最大 HP、MP/最大 MP、速度（决定行动顺序）、攻击力、防御力、技能列表。诅咒值与羁绊值属于长期系统字段，当前 Demo 不读取或改变。

> P4 篝火纵切加入一个**封顶成长原型**：战斗胜利按敌人数结算余烬；主角可在篝火消耗余烬升至最高 Lv.5，每级获得 1 技能点并按固定小幅度提高现有战斗属性；技能点只强化主角当前已有技能。它用于验证“战斗→回火→变强→再出发”的循环，不代表完整成长系统。七维自由加点、专精、装备 Build 与死亡掉魂仍属于扩展阶段 E3（见 §7.2），同伴属性在本 Demo 保持固定。

### 3.3 上场与换人

Demo 默认 2 个角色，始终同时上场；战斗系统支持我方 1~4 人同场（见 §3.1）。换人机制在交互层面预留入口，功能后续实现。

## 4. 羁绊—诅咒双表系统（长期开发任务，不属当前 Demo）

本系统是本作区别于通用 RPG 的设计内核。它把剧情大纲的"爱是一种枷锁"从抽象主题落地为可量化、可玩的机制。诅咒值在战斗中的具体效果见 §4.3；战斗流程本身见《战斗系统文档》。

> **立项边界**：本节只保存长期产品方向，不为当前 Demo 提供实现要求。只有在核心探索—战斗—篝火循环验证稳定后，才单独立项原型验证双表系统；届时再确定数值、UI、叙事内容和存档迁移。本轮篝火任务不承载营火羁绊对话或诅咒操作。

### 4.1 羁绊值（主角 ↔ 每位同伴）

五阶：**生疏 → 同行 → 熟识 → 信赖 → 无间**。长期系统首轮只验证主角与 1 名同伴的单条羁绊线。**羁绊有封顶**（牵挂阶为 10 格上限，每阶段 2 格，不可无限增长）。

**增长来源**：
- 完成角色支线任务：每段小幅增长
- 把缓解物用在该同伴身上：大幅增长
- 剧情节点：固定增长

**日常效果**：每升一阶解锁一段**营火对话**——这是承载该角色碎片化叙事与背景揭示的主要场所（叙事呈现见《对话系统文档》§3）。

**战斗效果（正向收益）**：
- 信赖：解锁主角与该同伴的强力**协同技**，在战斗中需要双方 MP 均高于 80
- 无间：解锁**互相替挡**（一方有概率替主角承受一次致命攻击并进行反击），**协同技**效果上升

### 4.2 诅咒值（仅被召者）

四阶：**平稳 → 躁动 → 侵蚀 → 濒临**。

**增长来源**：**只在主线节点推进时上涨**（呼应 §2.2 铁律——自由探索不推进）。

### 4.3 诅咒值的战斗效果

> **当前实现边界（2026-07-17）**：以下内容保留为长期设计，本轮攻击、防御和闪避均不读取诅咒值，也不改变任何诅咒数据。

> 2026-06-12 修订：废弃旧版"MP 消耗上升 / 暴击率 / 临时加点 / 失神跳过回合"方案。诅咒对战斗的影响集中到**主动操作层**——它让"出手"本身变得不可靠。

| 阶段（诅咒等级） | 攻击力度转盘 | 防御（格挡） | 闪避 |
|---|---|---|---|
| **平稳**（0 级） | 失误档占比 20%（基准） | 基准 MP 消耗 | 基准位移距离 |
| **躁动**（1 级） | 失误档占比 40% | 不完美格挡 MP 消耗稍增 | 位移距离稍减 |
| **侵蚀**（2 级） | 失误档占比 70% | 进一步增加 | 进一步减少 |
| **濒临**（3 级） | 失误档占比 85% | 进一步增加 | 进一步减少 |

- 转盘其余档区（完美/良好/普通）在剩余占比内**按原有比例缩放**。
- 视觉呈现：达到躁动及以上时，该角色**头像框周围出现紫色缠绕物**（通过替换头像框 sprite 实现，缠绕量随阶段加重），不使用数值/chip 显示——详见战斗界面 UX Spec（`design/ux/combat-screen.md`）。
- 格挡 MP 消耗与闪避位移的具体数值斜率待数值设计定稿。

### 4.4 两表的咬合——"爱是枷锁"的量化

诅咒值的**增长速率由羁绊值决定**：

> 某主线节点的诅咒增长 = 基础增长 × (1 + 羁绊系数)

羁绊越深，系数越高，该被召同伴在推进主线时诅咒涨得越快。于是玩家会亲历这个恶性循环：

1. 加深与同伴的羁绊 → 解锁其背景故事（叙事回报）+ 协同技（战斗回报）。
2. 但羁绊抬高了诅咒增长系数 → 下个主线节点该同伴诅咒值涨的更快。
3. 高诅咒 → 攻击转盘的失误区越来越大、格挡越来越贵、闪避越来越短 → 出手本身变得不可靠，既是负担又危险。
4. 手中只有一份缓解物 → 用在该同伴身上？用了，羁绊又涨 → 诅咒增长又快一档。

**你对一个角色付出的每一分爱，系统都记在诅咒的账上。** 这是本作的反讽内核在数值层的落点。

> 羁绊封顶的意义：玩家拥有一段"安全的爱的额度"——在封顶之内可以加深感情而不至于无限放大诅咒。封顶之上无法再投入，迫使玩家接受"我能给的爱是有限的"。

### 4.5 缓解物（稀缺资源）

缓解物是唯一能压制诅咒值的物品，**稀缺**，且**分配权在玩家手中**。

- **来源**：完成 npc 支线任务的最后章节，主线剧情。
- **效果**：降低指定被召者的诅咒值。
- **使用时机（关键限制）**：缓解物**只能在主线剧情的推进点使用**——即诅咒即将上涨的那一刻。它不是战斗道具，**无法在战斗中临时服用**；玩家随身携带它穿过险境，却只能在命运之门前为同伴使用。
- **战略张力**：永远不够救所有人。把缓解物用在谁身上，既影响战斗表现（降低其失神/死亡风险），又抬高该角色羁绊（因而长期看又加快其诅咒增长）——分配本身是一个两难。

> 缓解物机制是后期"命运分配"核心玩法的首轮原型。待长期系统立项后，再验证"稀缺资源 + 玩家分配 + 影响战斗与羁绊"这一结构。当前 Demo 的篝火只恢复 HP/MP，不提供缓解物或诅咒操作。

### 4.6 他者诅咒的可见性

长期系统首轮原型中，主角与同伴的诅咒值/羁绊值对玩家**可见**，以便验证机制；当前 Demo 不显示这些数值。正式内容阶段可考虑弱化同伴状态的数值显示、改以言行暗示。

## 6. 安全区与支持系统

### 6.1 安全区（聚落 / 篝火 / 礼拜堂）

| 功能 | Demo 实现 | 暂不做 |
|---|---|---|
| **NPC 对话** | 1~2 个 NPC，走近交互触发对话，逐字显示，翻页推进（对话系统见《对话系统文档》） | 分支对话、任务系统 |
| **恢复点** | 篝火/休息点，交互后全队 HP/MP 回满 | 需要消耗资源恢复 |
| **营火对话** | 不实现 | 羁绊系统立项后再制作同伴背景解锁与多线关系内容（见 §4.1） |
| **场景出口** | 走到边缘/出口进入野外 | 多区域选择 |

### 6.2 背包/物品系统

| 功能 | Demo 实现 | 暂不做 |
|---|---|---|
| **物品类型** | 消耗品（恢复 HP / 恢复 MP / 战斗投掷物） | 缓解物、装备类、任务物品 |
| **物品使用** | 战斗中通过"物品"指令使用；选物品→选目标 | 探索中使用物品；缓解物规则待长期羁绊—诅咒系统立项（见 §4.5） |
| **物品获取** | 野外拾取、战斗掉落 | 商店买卖 |
| **物品数据** | 记录名称、描述、效果类型、效果数值 | 堆叠上限（暂时无限）——完整堆叠/整理/丢弃链路见 §7.5 |

## 7. 扩展系统规划（通用部分，Demo 验证通过后）

以下系统不在 Demo 范围内，但预先记录方向，避免 Demo 决策与后续扩展冲突。战斗向的扩展（异常状态、动作化受击演出）见《战斗系统文档》。

### 7.1 音效系统（方向）

黑暗后日谈的氛围高度依赖音频。分层：BGM（安全区压抑 / 野外不安 / 战斗紧凑）、插曲（胜利/失败短曲）、环境音、SFX（界面/战斗/探索反馈）。调性方向：小调为主、不协和音程制造张力、节奏偏慢；攻击音偏机械金属质感，受击音偏低沉闷哼；走风格化 lo-fi 路线而非写实采样。Demo 阶段至少为"菜单确认/取消、攻击命中/受击"配占位音效以验证节奏反馈。详细分层与触发规则见附录 B。

### 7.2 成长系统（方向）

**保持原方向不变**：等级制为基础（提供大方向进度，避免玩家迷茫）+ 属性加点为成长抓手 + 装备/Build 为深度（真正的强度差异来自装备组合与技能路线）+ Soul-like 死亡惩罚（死亡丢失一半未使用经验值，在死亡地点成为临时拾取物；若未拾取且再次死亡则消失；**已分配的属性点不丢失**）。

> **P4 原型边界**：当前 Demo 只实现 §3.2 所述的 Lv.5 封顶余烬升级与单技能强化，用最少内容验证篝火成长闭环。它不实现下述七维属性选择、专精阈值、随机层、同伴成长或死亡掉魂；这些内容仍整体属于 E3，不能把原型的固定增量当作长期数值方案。

#### 属性体系（七维）

升级不再直接给固定 HP/MP，而是发放**属性点**由玩家自由分配，落到以下七项主属性：

| 属性 | 主要影响 | 备注 |
|---|---|---|
| **生命** | 最大 HP | 生存基石 |
| **魔力** | 最大 MP | 技能续航 |
| **速度** | 行动顺序 + 闪避概率 | 闪避属概率元素，见下方注 |
| **力量** | 物理伤害 | 普攻与物理技能 |
| **法力** | 魔力（法术）伤害 | 法术技能 |
| **韧性** | 防御力 | 减伤 |
| **幸运** | debuff 抗性 | 与 §4.3 的诅咒精神类 debuff、失神判定直接挂钩；亦可小幅提升掉落 |

> **与 MVP 的关系**：闪避、法术暴击等概率元素属于**扩展阶段**才引入，刻意不进 MVP（保持《战斗系统文档》的确定性战斗纯净）。成长系统上线时再统一开启随机层，且须保证"诅咒带来的可预期波动"仍是策略主轴、随机只作点缀。

#### 软上限与专精阈值

为避免"全点一项"碾压，单项属性采用**软上限**思路（参考魂系：超过某阈值后每点收益递减，鼓励复合 Build）。同时把"加点到一定数量"做成**专精解锁点**：某属性累计达 **5 点**解锁一档**小专精**（二选一），达 **10 点**解锁一档**大专精**（二选一）。专精是质变特性而非数值堆叠，让点数投入产生"流派"，且为被动技能。

专精方向示例（每档二选一，最终方案需配合实际数值与同类游戏体验调优）：

| 属性 | 5 点·小专精（二选一） | 10 点·大专精（二选一） |
|---|---|---|
| **生命** | 坚韧之躯（对异常状态的抵抗力增强）/ 余烬不熄（受击回少量 MP） | 向死而生（每场战斗首次濒死保留 1 HP 并短暂减伤）/ 血肉壁垒（HP 越高防御越高） |
| **魔力** | 涓流（每回合自然回 MP）/ 节俭（技能 MP 消耗下降） | 满弦起手（第一次技能不消耗 MP）/ 透支（MP 不足时可借 HP 施法） |
| **速度** | 先发（闪避概率提升）/ 残影（闪避后下次攻击增伤） | 连动（概率追加一次行动）/ 后发制人（被攻击后概率立即反击） |
| **力量** | 狂澜（HP 越低物理伤害越高，可与"濒临"诅咒同向叠加）/ 破甲（无视部分敌方防御） | 处决（对低 HP 敌人伤害激增）/ 威慑（发动攻击时有概率对另一名敌人造成此次攻击一半的伤害）|
| **法力** | 共鸣（法术命中追加少量真实伤害）/ 凝聚（法术伤害提升、消耗略升） | 法则贯穿（法术无视部分防御）/ 回响（法术有概率二次触发） |
| **韧性** | 格挡（受击有概率将该次伤害减半）/ 反震（被近战命中时反伤） | 磐石（免疫眩晕）/ 庇护（为队友分摊部分伤害，呼应 §4.1 替挡） |
| **幸运** | 净心（诅咒精神类 debuff 抗性提升）/ 拾遗（掉落率提升） | 命运垂青（每场战斗首次受到的 debuff/失神判定必定免疫）/ 时来运转（低 HP 时全属性小幅提升） |

> **参考与建议**：等级=大方向进度但避免数值膨胀；专精阈值=让点数产生"流派感"；死亡惩罚保留经验回收的紧张感、但不剥夺已固化的成长（参考魂系"魂"掉落，但本作已加点不丢，降低劝退）。建议 Demo 通过后先小规模验证"七维 + 双档专精"是否让 Build 有意义地分化，再决定是否叠加装备词条层。

### 7.3 周目识别入口（前向兼容预留）

保留**周目间轮回**（属大后期内容）。但在少量物件/事件上**预留周目状态字段**：MVP 阶段该字段恒为初始值、不产生任何效果，仅作为将来读取"第几周目"并改变自身状态的挂钩，避免日后回头改造这些对象。

推荐的周目锚点（皆为天然承载"他者回响"的物件）：
- 一个会说出既视感台词的 NPC
- 一件特定遗物

> 此为前向兼容设计，成本极低。具体字段挂钩方式见附录 B。

### 7.4 任务系统（方向）

**保持原方向**：任务生命周期为"未接取→已接取→已完成"，可放弃，支持并行（同类型互斥、主线优先、前置检查阶段拦截条件冲突）。任务类型含击杀/收集/对话/探索/护送。奖励按物品/经验/解锁区域/解锁角色等在不同时机派发。任务生命周期本身是一个简单状态机。

### 7.5 库存系统（方向）

把"地图拾取 → 入库 → 自动堆叠整理 → 查看/使用/丢弃"做成完整链路（MVP 只验证最小闭环，完整逻辑属扩展）：
1. **地图拾取**：可拾取物为带高亮的交互体，走近交互 → 入库（接口见附录），播放拾取提示。
2. **入库与堆叠**：背包是一份"物品 → 数量"的库存表。可堆叠物同类自动累加（设单堆上限，超出溢出为新堆）；不可堆叠物（任务物/独特物）各占一格。
3. **自动整理**：提供排序策略（类型/名称/获得时间/稀有度），整理只重排显示序、合并未满同类堆、清除空堆，不改总量。
4. **查看 / 使用 / 丢弃**：查看为网格/列表（图标 + 名称 + 数量 + 描述）；使用走 §6.2 效果分发，使用后数量−1、归零移除该堆；丢弃移除指定数量，贵重物二次确认。

> 分类：消耗品 / 战斗投掷物 / 缓解物 / 遗物（叙事物，见《对话系统文档》§3）/（扩展）装备、任务物。**缓解物**在背包中特殊标注，且按 §4.5 仅主线推进点可用、战斗内置灰。实现（数据结构、堆叠/整理算法、UI）见附录 B。

### 7.6 野外遭遇增强（方向）

强化 §5 的明雷遭遇（依赖 §7.2 等级系统，属扩展）：
- **偷袭（先制）**：地图上从**背后**接触触发偷袭——玩家绕到敌人背后接触 → 玩家偷袭；敌人背对接触玩家 → 敌人偷袭。**偷袭方在战斗开局获得额外一回合**（全员先制一轮）。判定用朝向：接触瞬间比较双方朝向与相对位置，落入背后扇形即偷袭。
- **等级化寻敌**：敌人遇到**等级远高于自己**的玩家时**主动逃跑**（进入逃逸 AI、拉开距离），减少高级玩家被低级杂兵反复骚扰；等级**远高于玩家**的敌人在地图上**身体泛红警示**，作危险预告。"远高于"的阈值可调。

> 设计意图：偷袭奖励潜行与走位（与明雷"可规避"一致）；等级化寻敌让大世界强弱关系**可读**。实现（背后扇形判定、逃逸 AI、泛红着色、先制写入战斗初始化）见附录 B。

## 8. 开发优先级与里程碑

### 8.1 Demo 阶段（P0 ~ P5）

核心目标：验证「探索 → 遭遇 → 战斗 → 返回/整备 → 再出发」核心循环。羁绊—诅咒双表系统不属于本阶段验收。

| 阶段 | 目标 | 可验证里程碑 | 预估工期 |
|---|---|---|---|
| **P0** | 场景切换骨架 | 能运行，在安全区与野外区来回切换，有过渡 | 1 轮 |
| **P1** | 野外探索 + 明雷敌人 | 4 方向移动，碰到巡逻敌人触发战斗 | 1 轮 |
| **P2** | 回合制战斗（最简版） | 打赢一场 1v1，有攻击/逃跑、HP 变化、胜负判定 | 2 轮 |
| **P3** | 队友 + 技能 + 物品 | 2 个可控角色，能放技能、用道具 | 2 轮 |
| **P4** | 安全区 + 篝火整备 | NPC 对话、篝火恢复/整备/传送，形成可重复游玩的返回闭环 | 2 轮 |

> "轮"指一次开发-审阅-修改的完整循环。
> P4 保留 2 轮用于完成篝火整备闭环及体验修正；P5 聚焦痕迹叙事与整体打磨。羁绊—诅咒另设长期原型，不占用 Demo 轮次。

## 9. 风险与缓解策略

| 风险 | 影响 | 缓解策略 |
|---|---|---|
| 回合制战斗节奏拖沓 | 核心体验差 | 先做最简版，快速体验后调数值 |
| 长期双表系统让玩家感到"被惩罚加深感情" | 主题传达失败（变成劝退而非悲剧） | 长期原型阶段先验证情感成立性；羁绊封顶给"安全额度"，并确保叙事与战斗回报足够明确 |
| Soul-like 高难度与回合制冲突 | 玩家挫败 | Demo 降低难度确保可通关，高难度机制后续迭代 |
| 占位素材无法传达氛围 | 审阅难判断方向 | 用色调弥补——暗色、低饱和、局部光源 |
| 长期诅咒系统仅靠主线推进，玩家可能"无限刷资源后再推进"以规避压力 | 削弱宿命感 | 长期原型阶段验证资源产出边界；缓解物不可无限刷取 |
| 战斗系统代码膨胀 | 维护困难 | 战斗拆分为独立子系统（见《战斗系统文档》附录） |

## 附录 B：技术实现参考（通用）

> 本附录收录与具体引擎相关的实现型细节及代码级术语，供程序实现时查阅。本作以 Godot 4.x 为目标引擎，但机制逻辑（正文）与引擎无关。战斗状态机/战斗 UI/受击演出的实现见《战斗系统文档》附录；对话框/对话系统技术架构的实现见《对话系统文档》附录。

### B.1 引擎与表现规格

- 引擎：Godot 4.x；目标平台经 Godot 导出至 macOS / Windows / Linux
- 像素风：纹理过滤设为 Nearest（`default_texture_filter=0`），保持边缘锐利；角色帧尺寸建议 64×64
- 占位素材：用 `ColorRect` / `Polygon2D` 实现，按阵营区分颜色（友方蓝、敌方红、NPC 绿），后续替换为 `AnimatedSprite2D`
- 窗口：游戏默认以全屏模式打开；可保留调试用切换入口，但正式游玩体验以全屏为基准
- 输入：Godot `InputMap`，WASD/方向键移动，`Z` 通用确认，`X` 通用取消/退出；核心 UI 不依赖鼠标，菜单、战斗、对话、调查与背包流程都必须支持键盘闭环

> **NPC 阵营翻转（敌对化）设计**：为支持"某 NPC 因事件由友转敌"的剧情（呼应 §1.1 派系余烬、§2.2"世界对被召者身份做出区别反应"），NPC 的叙事关系与分支归 Dialogic 管理；真正进入敌对玩法后的敌人状态归 `GameData`。典型触发点包括对话选择、身份暴露或请托结果。Demo 本轮不实现阵营翻转，也不预留字段或桥接层；该功能立项时再定义从叙事结果进入玩法状态的单一入口。

### B.2 场景与全局结构

- 三个独立场景：安全区、野外区、战斗，各为独立 `.tscn`，通过场景管理单例切换并传递上下文
- 三个 AutoLoad 单例：
  - `GameData`：Demo 玩法与世界事实（队伍成员及当前状态、背包/装备、当前场景、敌人状态）；现存诅咒值/羁绊值字段保持休眠，仅供长期系统立项时迁移
  - `Dialogic`：剧情阶段、分支选择、NPC 叙事关系与任务叙事进度；可只读查询 `GameData` 世界事实，不持有其镜像
  - `SceneManager`：场景切换接口 `change_scene(to_path, data)` + 过渡（全屏 `ColorRect` 遮罩，`Tween` 控制 alpha 淡入淡出 0.3s）
  - `BattleManager`：战斗生命周期（接收敌方配置→初始化→回合控制→胜负判定→结算写回）
- **战斗数据隔离**：`GameData` 持有真实队伍和背包状态；战斗开始时创建独立 `BattleSession`，进行中不写回全局。胜利提交 HP/MP、状态和物品消耗并登记敌人；成功逃跑提交消耗但不登记敌人；失败丢弃会话背包并重置队伍 HP/MP/状态。当前 Demo 的任何战斗结算都不读取或写入诅咒/羁绊字段。

### B.3 数据资源字段（Resource / .tres）

- `CharacterData`（基类）：id、display_name、max_hp、max_mp、speed、attack、defense、placeholder_color、sprite_frames
- `PlayerCharacterData`（继承）：skills、description；长期预留 exp、curse_value、bond_values（与各同伴），当前 Demo 不读取后两者；动作层字段（见《战斗系统文档》附录）
- `EnemyData`（继承）：ai_type（"hunter" / "kindled" / "beast"）、drop_table（item_data + drop_rate）；预留 level（野外遭遇判定用）、attack_archetype（弹幕模板键，见《战斗系统文档》附录）
- `SkillData`：id、name、description、mp_cost、power、target_type（single_enemy / single_ally / all_enemies）
- `ItemData`：id、name、description、item_type（Demo：consumable / battle_item；长期：palliative）、effect_type（Demo：heal_hp / heal_mp / damage；长期：reduce_curse）、effect_value；库存字段 stackable、max_stack、category、icon、sort_weight
- `Inventory`：`Array[InventorySlot]`，`InventorySlot{ item: ItemData, count: int }`（或 `Dictionary[item_id → count]`）；挂在 `GameData` 持久化

### B.4 目录约定与资产边界

- 工程目录：`scenes/`（场景）、`scripts/autoload|characters|battle|ui|items`（脚本）、`resources/characters|enemies|skills|items`（.tres 数据）、`assets/sprites/`（元资产产出）、`assets/derived/`（派生副本）、`assets/ui/`（UI 资产）、`assets/data/`（数据资源）
- **元资产只读**：`game/assets/sprites/` 由 sprite-pipeline 管理，`assets/` 下其它既有来源资产也不得修改、移动或覆盖。
- **允许的写入**：`assets/ui/`、`assets/data/` 可维护；需要加工元资产时，复制到 `assets/derived/` 后再编辑，不得反向覆盖来源文件。
- **删除限制**：删除任何资产都必须先获得开发者对具体目标的明确许可。

### B.5 音效系统实现细节

音乐过渡：场景切换 BGM 0.5s 淡出/淡入、可 0.2s 重叠；插曲播放时 BGM 衰减至 10%、结束后 1s 恢复；进战斗 0.3s 切战斗乐。SFX 并发：同类同帧最多 1 个、后者截断前者（伤害数字音例外可叠加）；优先级 受击音 > 命中音 > 菜单音。占位音效用合成音（正弦衰减、白噪 burst）按类型统一风格。

### B.6 库存系统实现（对应 §7.5）

- **数据**：见 B.3 的 `Inventory` / `InventorySlot` 与 `ItemData` 库存字段。
- **拾取**：地图拾取体 `on_interact` → `Inventory.add(item_id, n)`——可堆叠则找现有堆累加（超 `max_stack` 溢出新堆），不可堆叠则各占一格；触发拾取提示信号。
- **整理**：`sort(strategy)` 按类型/名称/时间/稀有度重排显示序，合并未满同类堆，清除空堆，不改总量。
- **使用 / 丢弃**：`use(slot, target)` 走 §6.2 效果分发，`count-1`、归零移除该堆；`drop(slot, n)` 移除指定数量，贵重物二次确认。
- **UI**：网格/列表（图标 + 数量 + 描述）；战斗内仅暴露可用项。缓解物分类与置灰规则待长期羁绊—诅咒系统立项。

### B.7 野外遭遇增强实现（对应 §7.6）

- **偷袭判定**：接触瞬间比较双方朝向与相对位置——攻击方位于目标**背后扇形**（如目标 `facing` 反向 ±60°）内即判偷袭；结果写入战斗初始化上下文 `ambush = {side, type}`，`BattleManager` 据此给偷袭方额外一回合（开局插入该方专属 `RoundStart`，或首轮 `TurnOrder` 置顶，见《战斗系统文档》附录战斗状态机）。
- **逃逸 AI**：明雷敌人持 `level`，巡逻时检测玩家 `level`，差值超 `FLEE_GAP` → 切逃逸状态（远离玩家、可离场不再触发战斗）。
- **危险警示**：`enemy.level − player.level > WARN_GAP` 时给精灵叠红色 `modulate`/边缘 Shader（"泛红"），作可读的强度预告。`FLEE_GAP`/`WARN_GAP` 可调。

> 依赖 §7.2 等级系统；Demo 无等级时这些行为关闭，仅预留 `level` 字段与朝向判定挂钩（前向兼容）。
